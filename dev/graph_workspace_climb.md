# Graph workspace: hill climb

The owner asked for a hill climb (2026-11-09): improve the GUI one change at a time. Started by Matthew; coordinator Marcus. The owner judges the prototype as preliminary and asks the team to build on the past designs and improve on them ("level up that").

## Rules for each step

1. One step changes one thing. If a step needs a second change to work, that change is its own earlier step.
2. One step is in progress per area: drawing (Jorge), views and interaction (Ida), wording (Matthew), seam (Marcus). Steps in different areas may run at the same time.
3. Before the change, record the check: what the user sees, and how to tell that it improved (a screenshot, a count, a time in milliseconds).
4. After the change, run the check on `graph-workspace` in Chrome, attach the before and after screenshots, and run `tsc` and `vitest`.
5. **Keep** the step only if the check improved and nothing else got worse. Otherwise **revert** it and record why. Then commit, and mark the step in the table.
6. Each step is on `graph-workspace` before the next step in the same area starts, so every step climbs from the last one.

## Past work to build on (read-only)

- `context/brain/digital-typology-hhgg-graph-fixed.html`: the earlier graph. Role colours, Receiving element (RE), Providing element (PE), Operative purpose (OP), Encounter function (EF) and Information flow direction (IFD) in the want details, motion with `requestAnimationFrame`.
- `context/topogee-repo/experiments/map-viewer/index.html`.
- `context/brain/recovered/branch-copies/a0b32f3cff6c/specifications/intake-graph-viewer-plan.md`. It specifies: interruptible eased transitions; the arrow keys move between connected elements; want detail is revealed when zoomed close; the base fades when a layer is viewed; positions stay stable during view changes.
