## Safety-relevant items (first)

1. **Running Roundtable as root to get AgentSight capture would run every agent as root.** The capture wrapper accepts only effective user ID 0 (`privilege_shortfall` in `crates/agent-monitor/src/capture.rs`). It is attached from inside the Roundtable server process (`on_started` calls `agent_monitor::Monitor::attach`). `acp-host` launches harnesses with no change of user (no `setuid` or `pre_exec` anywhere in `crates/acp-host/src`). So the only working way to get capture today is to run the whole server as root. Then every harness, and every shell command that the permission policy allows automatically, also runs as root. The tracer description must say this plainly and must not give "run as root" as the setup step. This affects upstream.tracer.agent rows 2, 6 and 8.
2. **A shared OpenRouter key can reach agents' shell commands.** The page ticks "share the key" by itself for `openrouter-acp` and `pi-acp`, and for an OpenCode seat whose model starts with `openrouter/` (`index.html`, the `harness.onchange` and `model.onchange` handlers). Only the repository's own adapter removes the key before it runs a shell command (`WITHHELD_ENV` in `adapters/openrouter-acp/src/tools.ts`). For Pi and OpenCode, nothing in Roundtable stops a shell command run by the agent from reading the key. The roster description (code.roster.participant row 4) should say so.
3. **The chair token is accepted as a URL query parameter on every `/api` route** (`require_chair` in `crates/roundtable-web/src/app.rs`). The page needs it in the query only for the event stream, because a browser `EventSource` cannot set headers. A token in a URL can end up in proxy logs and browser history. The description should record this (downstream.chair row 6). Accepting the query token only on `/api/events` would be a small hardening change. That goes beyond these rows, so I only note it here.
4. **When the workspace folder cannot be created, the permission boundary is built over a path that does not exist.** `Table::start` ignores the `create_dir_all` error. Both it and `ScopePolicy::new` (`crates/acp-host/src/permission.rs`) then fall back to the path as given when they cannot resolve it. Every seat then fails to start one after another, and only then does the table end ("no participant could start"). This is the reason for collection.workspace.shared rows 1 and 2.
