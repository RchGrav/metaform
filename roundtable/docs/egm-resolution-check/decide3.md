How the code was checked. I read the code under `crates/` and `adapters/`. While I worked, someone was splitting `crates/roundtable/src/engine.rs` and `turn.rs` into new files in the working tree (`agents.rs`, `handle.rs` and `table.rs` are new and not yet committed). All line numbers below for `engine.rs`, `turn.rs` and `rules.rs` refer to the committed version at `cde45e8`. The behaviour I describe is the committed behaviour. Line numbers for other files refer to the working tree, where those files are unchanged.

"The map" means `roundtable/metaform.json`. "Description" means an element's text layers in the map: `decisions`, `rules`, `gates` and `elephant`.

## Safety-relevant items

1. **JEV calls have no deadline, so a JEV call that never answers stops the table.** This is outside my rows, and I found it while checking selector row 3. The HTTP client is built with no timeout (`roundtable-web/src/app.rs:133`), and `jev.ask` sets none (`jev.rs:148-153`). With judging on, the next turn waits for JEV's verdict (RT-G10, `engine.rs:510-513`), and with topics on, a poll waits for JEV's scoring (`engine.rs:503-508`). A connection that hangs without closing would stop the table with no end. This goes against the owner's decision of 2026-11-05 in the map (code.gate.quality): "when it is on and JEV fails or does not answer within a short deadline, the contribution is distributed unjudged ... the table never waits on JEV". Session decision 14 ("No timeouts") is about agents running long, not about JEV. Recommendation, which goes beyond this task: put a short deadline on the JEV request only. The unjudged path that already exists then handles it. The same section of code shows a second stop, already marked "Against the owner" (selector row 1): while a poll waits for a busy agent (RT-G21), nobody gets the turn to speak.
2. **A registry harness can show as available and then fail to start** (registry row 3). It wastes a seat, and the failure is loud, but the chair is misled at selection. The fix is one line.
3. **The registry environment filter covers only direct npx and uvx launches** (registry row 4). For `acpr <id>`, Roundtable passes none of the entry's variables, but how acpr handles them is not checked here. Record this as an open boundary, not as protected.
4. **Two participants at one table can share a generated name** (identity row 4). The resolution says otherwise. RT-G15 prevents a rating going to the wrong identity, and profiles are keyed by session, so nothing is misattributed. The effect is only a refused rating.
