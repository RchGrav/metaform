## Safety-relevant items

1. **Agent processes are killed whenever an ACP connection ends, not only at shutdown** (code.client.agent row 8). `process.rs` starts the 1-second, then 2-second sequence ending in SIGKILL on any connection end. That includes a connection that fails during a table while the agent may be writing files. When the main process exits, the rest of its process group is killed with no grace period. The gate registry already records that SIGKILL can damage workspace files, git state and session records. The owner called the timing aggressive, and session decision 14 says agents run until completion. The description must state the real scope.
2. **The OpenRouter key reaches an agent only when its seat opts in** (code.catalog.model row 11). That is the safe default. When a seat opts in, any shell command the agent runs can read the key. It is the same key used for JEV and for the catalog, so that agent can spend on the owner's OpenRouter account. The page turns the opt-in on for Pi, the OpenRouter adapter, and OpenCode with an `openrouter/` model. The description should say this plainly.
3. **The bus keeps going after a poisoned lock** (code.bus.event row 8). I chose to keep recovering the lock, because treating it as fatal would stop every component and the table. That choice is safe only if the name check moves ahead of the sequence increment, so that the one known panic leaves the registry untouched. Without that move, a duplicate event name in a debug build can leave one queue missing an event, with no signal.
4. **A key lost during a table gives no warning** (code.gate.quality row 13). If the JEV key is cleared during a table, every later message is shared unjudged and only an event note records it. The start-of-table warning is not repeated. This is not dangerous, but the chair can lose the judging step without noticing.
