## How to work

- **Understand before writing.** When the owner explains something, his examples and analogies explain it; they never define it, limit it, or become a rule. Before writing any meaning into the project, say back what you understood in your own words, ask what is unclear, and wait for his go-ahead. Then write it in your words and show it.
- **His files are his.** `rich/intake.axiom` and `rich/metaform.axiom` are authored text. Draft changes and show them; he edits or approves; then the served copies in `src/metaform/modules/intake/resources/` become exact copies of his. Nothing else restates what they say.
- **One place for each meaning.** Tool text, help, connect instructions and docs say what a call does and point to the procedure or the spec for meaning. When something changes, change the one place and remove the old text; never leave two versions or add an amendment to a record.
- **The tools fit the procedure.** Where the procedure and a tool disagree, the tool changes, unless the procedure is plainly wrong, in which case say so and let him decide.
- **Never name or quote the owner** anywhere in the repository. `tests/test_shipped_text.py` checks `src` and `tests`.
- **Test budget, CLAUDE.md:** run only the tests for what changed while working; run the default `pytest` (about 70 seconds, no browser tests) once before each commit; browser tests only for page changes, by name. Never rerun a suite that passed.
- **A running MCP server keeps the code it started with.** After changing the intake or the server, the session and any agent using it need `/mcp` reconnected or a fresh session.
- **Name collisions:** grep a name before adding it at module level. Today `_join_refs` and `SHAPE` were both taken in the intake module, and `app.js` has had duplicate declarations.
