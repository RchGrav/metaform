## Practical conclusion

Preserve the chassis/module foundation and the empty Python scaffold. Reuse the storage-free literal metadata parser, declarative records and async invocation mechanics where their observed behavior matches the rebuild. Adapt loader lifecycle, settings and call contexts behind new runtime-state and graph services. Replace the template's SQL/table/transaction recipes and automatic CLI-to-MCP mirroring. Clean up the operator CLI incrementally around its existing parser and error contracts. None of these recommendations establishes LadybugDB compatibility or implementation readiness.

## Specific operator-CLI cleanup proposal

These are reviewer proposals, not additional settled owner commands.

1. **Keep the operational chassis:** project registration/selection, module inventory/enablement, configuration, installation/provisioning, snapshots/import/export and diagnostics. Existing responsibilities are visible in `cli.VERBS` (`cli.py:1041-1046`) and chassis ownership in BASE-001/002 (`specifications/04-chassis-modules.md:12-29`). Organize operator help around these tasks while keeping familiar invocation forms during refinement. Retain generic module dispatch, not module-specific branches.
2. **Consolidate dispatch metadata:** replace manually synchronized `cli.VERBS`, `docs.command` records (`cli.py:1209` onward), `loader.RESERVED` and their completion/help consumers with one operator-command declaration source. C8 is the concrete drift this prevents. Do not move all feature commands into chassis.
3. **Separate configuration, place and availability:** keep `set/unset` for configuration. Revisit folder `modules` as a presentation setting, not agent authority, and avoid importing legacy folder-as-identity claims (`specifications/05-cli-settings.md:575-584`) into per-agent epoch/identity state. The archive explicitly requires independent contexts and unrestricted navigation. A dynamic blacklist is the governing restriction model. CLI-040 already records the unfinished separation (`:604-612`).
4. **Replace storage administration internals:** `cli.query_` constructs legacy `Store` (`cli.py:870-884`), import/export call legacy data/archive services, and prompts/settings/version housekeeping reach SQLite. Define target snapshot/runtime administration services before retaining their operational front ends. A maintenance query command is not the agent's semantic API, and raw query ability must not be required to submit an intake or revise a Join.
5. **Make read-only operational paths explicit:** ordinary `_command` calls execute `home.make_private`, module refresh/discovery and `install.backstage` before help/status routing (`cli.py:1564-1574`). `backstage` updates install/version metadata (`install.py:943-960`). This is intentional legacy housekeeping, not a claim that help currently has zero writes. Preserve necessary compatibility checks while identifying which diagnostic/help paths can operate from packaged declarations without opening/mutating runtime stores. `--version` already bypasses those steps (`cli.py:1561-1563`).
6. **Keep shared argument/error primitives, remove interface identity:** an operator can still use `metaform <module> <verb>` while agents use compact semantic submissions, revisions and the three specified retrieval presentations. Both may call a domain service. Neither should parse the other's serialized command line. Automatic prompt rewriting by `Context.calls` (`module.py:699-709`) must not define the semantic MCP contract.
7. **Carry only explicit policy:** existing `Verb.person_says/person_decides`, `Setting.person_only` and role-control machinery (`module.py:189-211`; `settings.py:75-81`, `:841-884`; `cli.py:1165-1185`) are legacy behavior to evaluate, not an authorization hierarchy adopted by default. Preserve owner direction and configured dynamic blacklists without inventing a mandatory reviewer or approval pipeline. Detailed policy extraction belongs in the runtime/interface refinement.
