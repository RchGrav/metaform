Project vision as the founder explained it on 2026-10-30. The working intake document is `~/brain/Intake.xml`.

**Prime focus.** The project's prime focus is contextual precision, meaning that an agent gets what its job needs at its position. The founder proposes a token meter that charges agents for everything we control. It must be consistent and comparative, not exact, because its job is comparison.

**Intake terms.** The terms were tuned and tested across frontier models. They are somewhat ambiguous by design, because they are contextual anchors. They become precise only in combination with the operation taking place. That is why about 8,000 tokens have to be in an agent's head before it can understand them, and why the terms resolve differently in different media.

**Decomposition.** The founder proposes slicing intake into smaller contextual blocks that state what an agent needs for each job, such as a full intake or expanding the map, delivered on demand. Most agents using the system do not need this understanding, and it would hurt them more than help. Specialist agents could carry it, and it could be changed through them.

**Risk it addresses.** If an agent changes the terms, code intake still works, but by the founder's estimate about half the agent benefit is lost. Everything collapses into the register of the agent that touched it, and nobody notices until the metaform is used on non-code work. The wording is protected in `AGENTS.md` for this reason.

**Reach.** Intake has been tested across document types, including code, photos, stories and films. Different agents can produce different maps of one thing, and the result is still stable and tends to grow with functionality, not change. Memories, specs and docs then live in that construct, which speaks in functionality and not in code or file names.

**Skills.** A prompt can take a ticket and a functional perspective and create a skill that appears only when work returns to that part of a project. This is why the system can hold many more skills than a flat list, which costs context on every agent.

**How to apply:** Use this as the reason behind intake, context delivery and skills decisions.
