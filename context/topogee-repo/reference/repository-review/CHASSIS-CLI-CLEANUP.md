## Public base and template storage adaptation

When a template user follows `modules/template/__init__.py:26`, they receive `Tables`, `Table`, `Column`, `Index`, `Store.atomic`, `DATA_SOURCE` and `Table.from_sql` recipes. This is direct storage coupling, even though imports come from the public base.

`src/metaform/context.py:31` constructs concrete Store. `data/store.py:71` creates Session and `:117` handles SQLite integrity errors. `data/session.py:36` exposes `sqlite3.Connection` and Cursor, `:140` opens SQLite with Row and `BEGIN IMMEDIATE`. `data/tables.py:3` documents separate module `.sqlite3` files. A replacement driver alone cannot preserve these interfaces over the target graph model.

The smallest responsible change is a new public persistence/domain boundary for module state and graph publication, followed by adapted context injection, extension schema/version/cleanup semantics and template examples. Preserve retained-data readability for disabled/removed modules where intended, while specifying its target format. The legacy `tests/test_module_data_source.py:33`, `:93`, `:111` establishes useful retained-declaration behavior. `tests/test_module_tables.py:104`, `:129` establishes physical SQL tables/indexed paging, which is implementation-specific evidence.

Settings declarations can remain the source of operator type/default/help metadata. `settings.py:56`, `:422`, `:333` supports this. Persistence at `settings.py:373`, `:417`, `:555` reaches `home.settings_db` and SQL. Preserve useful inheritance/validation after adapting state. Do not carry `EMPTY_IS_ALL` at `settings.py:542` into the target projection's distinction between unspecified and explicitly empty layer selection. Settings, glue, carry-once receipts and prompts have no assumed SQLite exception.

## Operator CLI responsibilities and cleanup

The following are proposals for refinement, not a final renamed command inventory.

1. Keep the chassis operational responsibilities: project selection/registration, module inventory and enablement, configuration, installation/provisioning, snapshots/import/export and diagnostics. Existing entry points are visible in `cli.py:1041`. Feature modules retain their own operator entry points.
2. Consolidate command declaration metadata. Routing, help, reserved module names and completion must use the same operator command registry. The `start`/`demo` drift is a concrete justification for this change.
3. Keep familiar typed nouns, positive/negative boolean forms, `--`, structured stdout, diagnostic stderr, actionable Error/Next and exit status. These are useful tested operator behaviors. Do not make agents reconstruct shell grammar to express semantic changes.
4. Separate configuration and presentation from identity or authority. Folder `modules`/`layers` preferences must not become per-agent identity or an inferred permission hierarchy. Independent participant/context/epoch state and explicit dynamic blacklists govern the target. Legacy CLI-040 already records unfinished separation at `specifications/05-cli-settings.md:604`.
5. Define target administration services before retaining storage-facing commands. `cli.query_` at `cli.py:870` constructs Store, while imports/exports/settings/prompts use legacy archives and SQLite services. Preserve the operator's intended administrative outcome with new snapshot/runtime records. Raw database access must never be necessary for ordinary semantic intake or refinement.
6. Make diagnostic/help side effects explicit. `_command` at `cli.py:1564` calls privacy/refresh/installation housekeeping before ordinary routing. `install.backstage` at `install.py:943` writes version metadata. This is intentional legacy housekeeping, not evidence of read-only help. Consider declaration-only help/status paths where no persistent mutation is needed. `--version` already bypasses that path at `cli.py:1561`.
7. Separate operator and MCP bindings. `module.py:3` and `Context.calls` at `:699` currently equate surfaces and rewrite command references. The semantic MCP service may share domain operations with CLI but owns its own objects, schemas, version/conflict/readback and context contracts. Loader validation of every verb as an MCP name at `loader.py:214` must no longer impose that identity.
8. Carry forward explicit restrictions only. Legacy `Verb.person_says/person_decides`, `Setting.person_only` and role policy at `module.py:189`, `settings.py:75`, `:841`, `cli.py:1165` are not automatic authorization requirements for the rebuild. Preserve owner direction/configured blacklist without inventing a mandatory approval/reviewer pipeline.
