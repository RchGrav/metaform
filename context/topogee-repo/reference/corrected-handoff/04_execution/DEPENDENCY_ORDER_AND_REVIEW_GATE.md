# Implementation ordering with anti-contamination gate

The intent is to deliver a correct legitimate tool under finite budget. Stabilize the system's external contract before spending on an elaborate interface or another massive parallel agent run. Each stage must produce a small reviewable result with explicit stop criteria.

## Stage 0 — freeze authority / cheap reproducible validation (no coding)

- Copy current canonical XML and JSON unchanged; fingerprint sources.
- Mark historical drafts and older schema variants **read-only evidence**, not instructions.
- Validate the corrected logical schema against a minimal join example; produce discrepancies rather than rewriting original semantics.
- **Gate:** owner reviews terminology, provider join placement, optional node-level EF, ICE/group mismatch; no design guessed from old code.

## Stage 1 — complete bounded specification and independent critique

- Expand the corrected candidate into requirement-by-requirement normative spec with explicit MCP 2-tool functional contract, three views, schema, batch and error cases, receipts, lifecycle boundaries and acceptance fixtures.
- Inspect original Canonical Intake process for every substantive semantic check; make sure no essential reasoning step is lost.
- Optionally use BMAD for independent contradiction/acceptance testing; BMAD instructions do not override Metaform's language or owner authority.
- **Gate:** owner verifies source-to-requirement crosswalk and specifically reviews all prompt reuse candidates.

## Stage 2 — short read-only legacy knowledge extraction (after spec exists)

- Mount old repository read-only; no source writes and no reuse/import of old modules, commands or database code. Extract: function-bearing mechanisms, module contracts worth retaining, dependency/ICE coupling, external integration restrictions, exact prompts/skills and their call sites, missing behavior.
- Record each as `source path/commit`, `observed fact`, `potential function`, `new spec clause`, `conflict`, `recommendation`, and classify prompts as retain/rewrite/reject/needs review. **No auto promotion.**
- **Gate:** the owner reviews the entire functional/prompt extraction package and all proposed additions before any agent is granted the clean implementation tree.

## Stage 3 — clean isolated build

- Prefer existing Mac Studio Linux containers or WSL2; correctness doesn't depend on host. Isolate rebuild workspace from old source search paths. Make legacy repo unavailable to routine builder sessions; allow targeted read-only lookups only with an explicit question and provenance.
- Preserve useful chassis/module extension semantics through a versioned public contract; initial Python chassis/DAO, Node/TypeScript MCP boundary, backend storage behind DAO. Rust core remains a later engineering candidate.
- Implement in dependency order: logical namespace and physical DAO schema → provider join semantics/indexes and transactional apply → 3-mode view and adjacency query → intake batching/validation/closure → knowledge + receipts/inboxes → directed messaging and lifecycle → facilitator/peer selection and scoring → embodiment adapters and nonessential GUI.
- **Gate after each slice:** spec-derived correctness tests, no informational paid turns, no duplicate tool/recipient context, measurable token and spend ledger, reversible rollback.

## Stage 4 — conformance and product proof

- Real operator workflow: intake a small project, edit/map it, retrieve local/global/knowledge views, send node notice, reuse an idle agent, handoff on context threshold, select agent/team, retrieve historical agent and commits.
- Measure *completed work* and dollar/token cost vs hand-coded database-editing interactions. Test failure/restart/idempotency and node reader races.
- Do not substitute large volumes of green unit tests for a single successful end-to-end run.

## Cost containment

Run design checks/fixtures without paid model fan-out first. Default to one worker in spec validation; add a second as a critical reviewer only where fault-finding has a defined benefit. No automatic assessment chain, role-creation cascade, informational work completion prompts, or invisible spends. Set a budget ceiling before each paid test and stop when it is reached.
