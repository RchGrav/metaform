# Final adjudication clarifications

The full twelve-finding decisions are in `resolution.md`. These clarifications address the final-round disagreement.

1. **GF2: preserve the explicit rule pending integration verification.** `element.md` rule 0 requires chair commands and JEV results to be published as events. Awaited mpsc delivery can avoid polling while still failing that explicit publication requirement. Thus confirming the reviewer's engine routes would demonstrate an integration gap; it would not authorize changing the rule to effects-only. Conversely, finding actual publication of the original commands and results would undermine the claimed omission. The engine files are absent, so this snapshot cannot settle that factual check. The immediate correction is to label implementation coverage unverified, retain the requirement, and record the conditional integration gap.

2. **GF3: choose release enforcement, rather than documentation alone.** The source identifies event names as record identities and keeps a name-to-type map, but guards collisions with `debug_assert!`. Release collisions preserve typed routing while corrupting the meaning of name-based records. Enforce the existing contract with an unconditional assertion before sequence increment or enqueueing. A release test must reject a second type with the same name and observe no conflicting payload in a tap. This is a deliberate code correction, not merely optional wording.

3. **GF6: cache the first outcome, including failure.** Lines 55–58 first run serialization inside `get_or_init`, turn failure into `None`, then serialize again in the `None` branch. Subsequent calls keep entering that branch. For an always-failing serializer, N calls yield N+1 attempts. Caching only a later success would still violate the stated one-attempt contract. The chosen correction caches success or failure once across cloned envelopes; a counter-based test must observe exactly one attempt for repeated/concurrent JSON requests. A shareable error representation or deliberate error reconstruction is needed because `serde_json::Error` cannot simply be cloned.

4. **GF5: keep the ordering mutex and correct the latency claim.** The lock encloses fan-out to all receivers, so its duration is not guaranteed brief. The defensible promise is no waiting for queue capacity or consumer reads, not bounded latency or lock-free publication. Retain the mutex and qualify the description and crate rustdoc.

GF1/GF7 remain one description contradiction with one fix. GF4 and GF8–GF12 remain documentation/context findings, with GF11 additionally identifying an integration precondition: register the record tap before producers start and drain it on shutdown. None establishes a need for replay or for changing typed subscription filtering.
