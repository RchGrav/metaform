# DenseEscort: final reconciliation and observable checks

These refinements supplement the per-finding decisions in `resolution.md`.

**GF1: require a useful directory before launching participants.** Reporting a warning and continuing is insufficient: `Table::start` currently discards directory-creation errors before publishing the workspace path and launching seats. Preserve the asynchronous startup API, but emit an error identifying the path and filesystem error, end the table, and launch no seats if directory creation or canonicalization fails. Observable check: configure an existing regular file as the workspace; expect a workspace error and table-ended event, with no participant launch or `TableOpened`. A preexisting directory containing an artifact must still start and retain the artifact. This verifies both failure handling and intentional reuse.

**GF2: distinguish policy requests from a harness sandbox.** The config source describes two alternatives: requests reaching Roundtable's scope policy, or an operating-system sandbox confining writes. Therefore the description must not say all writes are mediated by `ScopePolicy`. Configuring a mode key is also not evidence it succeeded: settings failures produce a warning and the seat can still join. Observable counterexample to a universal policy-routing claim: a Codex harness in `workspace-write` mode confines writes using its sandbox without forwarding every filesystem operation for Roundtable approval. Shared cwd specifies location, not a write grant.

**GF8/GF11: partly uphold the clarification, reject a claimed evaluation exemption.** AlloyedWalrus correctly observes that the existing owner-acceptance sentence already answers whether leaving files unjudged was intentional. AquaticHacker correctly asks to connect that fact to the supporting-artifact convention. The correction is: “Supporting files are not judged; the evaluated reply must still explain the substantive point and what the artifact establishes.” The supplied prompt says a file reference alone is insufficient. It does not establish an exemption from message evaluation. Observable documentation check: a reader must answer both “Are file contents judged?” (no, by accepted design) and “Does a file link make an otherwise unexplained reply sufficient?” (no). A rule explicitly accepting bare-link replies would undermine this interpretation, but the provided prompt states the opposite.

**GF10: document absence of coordination without promising last-writer-wins.** Tools can append, modify a file in place, or replace it atomically. Those operations have different concurrent outcomes. Record that this layer supplies no coordination; do not promise one deterministic result for all conflicting edits.

**GF12: uphold discoverability, use a shared glossary.** Map-wide vocabulary belongs in a map-wide glossary. That is a reason to link authoritative definitions, not a reason to leave the reader unable to interpret the fields. Do not guess `SE` or formal intent direction from this element. A readily accessible existing schema defining those terms would resolve or undermine this finding without adding local definitions.
