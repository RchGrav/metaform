# Example layers

These are example layers where data exists. The data in a layer is presented in the same structure, in JSON, as it would be structured in tooling driven by the Metaform, across all of its paradigms. For example, skills are encoded at, or filtered dynamically by, functional intelligence: the Metaform presents contextual skills through functional perception, a direct analog to the spatial intelligence of an embodied environment.

## The base (not a layer)

The base is what intake records. The layers sit over it.

- Elements, joins and subtypes.
- The purpose record on each receiving element (RE): its Operative Purpose (OP), the Encounter Function (EF) of the providing element (PE) that serves it, and the information flow direction (IFD).
- Defining, substantial and notable elements (DE, SE, NE), parametric values, and indivisibly coupled elements (ICE) with their Blocks.

## Layers over the base

| Layer | Data it holds |
|---|---|
| Sources | Reference links to entry points in the code base. |
| Memory | The memory graph shown at nodes: what happened in the work. |
| Property | One property per layer: a language, a framework, a file format, an encoding, a style, a protocol version. |
| Knowledge | Whatever the prompt that builds it asks for: imperatives, best practices, foresight. |
| Prompt | A prompt stored at a join. |
| Skills & Tools | Specialist skills for the functionality, and the tools offered there. |
| Specification | The Objective Purpose requirements, the local specification and the interface constraints at the node. |
| Documentation | Documentation and the reasoning behind it, for the node. |
| Tasks | Tickets docked at the node, their board state and their history. |
