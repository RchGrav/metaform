# Evidence-led debugging

Use prepared project understanding and the actual failure evidence to identify plausible causes. Choose a focused observation or experiment that distinguishes the consequential hypotheses. Record the candidate, source location, result and remaining uncertainty in the existing work record.

Separate what happened from why you infer it happened. Check the responsible path and its relevant dependents. Repair the cause while preserving the functionality and experience the path serves. A marker disappearing or a memory being corrected does not establish that the underlying implementation was repaired.

Preserve reusable causes, constraints and dependencies in memory at their functional entry points, with meaningful evidence references. Keep incident chronology in the work record.
