# template

The empty start of every Metaform module. Copy this folder to begin a module; every heading below is one a module's README answers.

## Purpose

What the module is for, in two to four sentences.

## Template version

The template changelog version this module started from: 0.2.0.

## Declaration

`SUPPORTED_OS`, `DEPENDENCIES`, `SHIPS_DISABLED` and `MODULE`, with what each is set to and why.

### Toolbar items and panes

The tools the module adds to the web GUI's toolbar, `MODULE.toolbar`, and the panes it adds to its workspace, `MODULE.panes`, with why a person uses each. Declare them with `ToolbarItem` and `Pane` of `metaform.module`; they are defaults the person rearranges on the page, and a disabled module's tools and panes go with it.

A `ToolbarItem(id, title, description, icon=...)` does exactly one thing: `verb=` runs one of the module's verbs with fixed `arguments=`, never one that reaches agents or the network; `pane=` shows a pane, the module's own by id or another's as `<module>.<id>`; `page=` runs a command the page carries, such as `search` or `add-task`; `link=` opens an `http(s)://` or `metaform://` address or a file under `resources/`. `selection=` names the noun that receives the selected node's address, and the tool is off while nothing is selected. `group=` shares one toolbar slot with the tools of that group, the first shown and the rest behind it; `placement=` is `toolbar` or `extra`, the tools behind the toolbar's last slot; `order=` sorts, lowest first; `shortcut=` is a key such as `Alt+B`.

A `Pane(id, title, description, icon=...)` shows exactly one thing: `verb=`, a `read` verb of the module, run with `arguments=` and the selection whenever the pane shows, the selection changes or the map changes; `page=`, a view the page draws itself; or `resource=`, a `.md`, `.txt` or `.html` file under `resources/`, the HTML in a sandboxed frame. `area=` is where it starts, `left`, `main`, `right`, `bottom` or `float`; `group=` the tab group it joins there; `visible=` whether it starts on; `order=`, `min_width=` and `min_height=` its place and least size. Keep what a person reads or types into on the right and leave the left to the maps.

The description is one line saying why a person uses it, not its title again; it is the tooltip. The icon is a name from `metaform.module.ICONS` or an SVG under `resources/`. Ids are lowercase letters, digits and hyphens, unique in the module. The loader refuses a module whose tool or pane names a verb it does not declare, a noun its verb does not take, a pane verb that writes, or a file it does not carry. The template's `about` tool shows its `about` pane, `resources/pane.md`.

## Common base used

Each call's `ctx.identity` is a fresh dictionary of transport-supplied IDs. The Paperclip HTTP gateway supplies
`agent_id`, `issue_id` and `run_id`; missing or blank headers leave those keys out. `context(..., identity=...)`
copies its input. These IDs carry context, without changing process environment or authority. `ctx.session`
keeps delivery records apart per agent and run, including background MCP tasks, so another run receives its own context.

Which of `metaform.module`, `metaform.settings`, `metaform.data`, `metaform.events`, `metaform.prompt_files`, `metaform.home`, `metaform.outline`, `metaform.finish_xml`, `metaform.jev`, `metaform.frames` and `metaform.skills` the module uses, and for what. Through `metaform.jev` a module asks Jev, the optional decision model, for a typed decision, `jev.pick_one(folder, question, options, state, title=, why=, address=)` and its kin, and keeps its plain behaviour when the answer is None or not `sure`, CHANGE-ORDER-2026-10-07 item 6 (P185); a module's own decision point passes `decision='<module>.<point>'`, the name the person lists in `jev_decisions`. Through `metaform.prompt_files` a module reads its own `resources/prompts.xml`, `prompt_files.text(resources.files(__name__), name)`, or `prompt_files.required` when a missing prompt is a defect, MCP-031. Through `metaform.data` a module reads and writes the map's layers and the work records: the condition of an element or a join, a subtype join included, `missing` (the thing does not exist at all, or is not built yet), `broken` (exists, not working, not connected or orphaned), `flawed` (works but is not right), `enhancement` (works, could be better) or `exclude` (outside the scope, or conflicting with a superseding specification), kept apart from the map with a note and a task, `store.add_work`, `store.edit_work`, `store.finish_work` and `store.work`, MAP-046 and STORE-042; hello's `todo` shows it. `store.finish_work` takes `outcome`, `completed` unless the work was `cancelled` or `failed`, the terminal states of `metaform.data.status`, and the record carries it, P232. Through `metaform.data` a module also declares tables of its own, `Tables`, `Table`, `Column` and `Index`, and reads and writes them in `store.tables()`, STORE-045; hello's `visit`, `note` and `notes` show it. Through `metaform.module` a module adds to the read of a node with `Module(node_read=...)`, a function of the context and the node that returns plain data, shown under the module's id in `map where` and `map node`, or None for nothing, BASE-035; hello's `node_read` shows it. A module keeps its own fields on a work record, such as a dispatched agent's session id, in a table of its own keyed by the work id, STORE-045, so the work table's layout never changes for them, and shows them with `Module(work_read=...)`, a function of the context and the work record that returns plain data, shown under the module's id in `map work id=<id>`, or None for nothing, BASE-035; hello's `todo` and `work_read` show it. A module says how much it holds at a node, and never what, with `Module(node_count=...)`, a function of the context and a tuple of element addresses that returns a `Count`: the word for one and for several, at each address how many, how many the last session there wrote and how many the calling session wrote, and its `counts` prompt, the line saying how to read them; an agent orienting on its node is told these counts for the node and its direct neighbours once per session, and after that only what changed, MCP-039. memory's `node_count` shows it. A module numbers what it writes at an address, MCP-037: each item, a memory, a question, a ticket, takes `store.number(address)`, the next number of that address's one counter in the project's database, which counts up from 1 and never reuses a number, kept with the item and shown in hex, `metaform.data.reference(address, n)`, `code.manager.route#1f`; a module's upgrade numbers the items it already holds with `tx.number(address)` in creation order. Every such write carries a short title, and one that records knowledge or a decision a short why; the verb refuses one without them with `metaform.module.titled(ctx, what, title, why, why_needed=...)`, whose one-line next step says which is missing. The module reads one item back with `Module(item_read=...)`, a function of the context, the address and the number that returns plain data, `kind`, `title`, `why`, `body` and `links`, or None, served at `metaform://<address>#<n>` and by `map item`. memory's `item_read` shows it. It lists them with `Module(items_at=...)`, `items_at(ctx, address, before, limit)`, a function or coroutine returning those numbered below `before` (all when None), newest first, at most `limit`, each `number`, `kind`, `title` and `why`, in one read, and names the kinds it numbers with `Module(item_kinds=(...))`, so a list asked for other kinds skips it; `metaform.module.node_items` merges every module's list for a node's brief, and `items_page` pages it with MCP's opaque `cursor` and `nextCursor`. A module with `item_read` and no `items_at` is read number by number, the slow way. memory's `items_at` shows it.

Shipped modules and a user's modules share these public services, BASE-004 and QUAL-016, so an extension can use the same capabilities without importing private chassis code. `metaform.module` offers `project_for(folder, named=None)` for folder context, `surface(folder)`, `on_surface(group, folder)`, `aliases(folder)`, `command_summary(name)` and `chassis_version()` to describe the available commands, and `refresh_modules()` for a long-running process to load or drop modules enabled or disabled since it started. `settings.toggled_layers(folder)` reads the folder's chosen layers. A module that puts what was built on the map grows the base with `Store.grow_element` and `Store.grow_join` under the intake's rules, each with a reason, evidence and `by=metaform.data.author(ctx.surface)`; a module that keeps records by address subscribes to `map.moved` to follow an element renamed or merged by `map refine to_address=`. `metaform.events` offers `listen(module, handler)` for a process with no `Context`, the same as `ctx.listen`, and `announce(folder, surface)` for a long-running process to publish the pending map changes of a call it ran.

A module serves read-only texts over MCP with `Module(resources=...)`, each a `Resource(uri, name, description, verb)` of `metaform.module` read by calling `verb`, MCP-037. A URI with `{field}` parts, such as `metaform://<module>/item{item}`, is a resource template: listed among the resource templates, and read by calling `verb` with the fields as its nouns, so every field names one of its nouns; the intake module's fixed resources show the first; no module shipped today declares a template.

`metaform.home` offers the home and its projects: `home()`, `project(id)` and `projects()`; `to_clear(project)` and `clear_project(project)`; `backups(project)` and `restore_project(project, name=None)`; and `not_empty(project)`, `removal_caution(project)` and `remove_project(project)`. The caller obtains the operation's confirmation through its declared `Verb.caution`. `remove_project` enforces that the project is empty and keeps its source files, history and backups. `file_lock(path, wait=True)` is an exclusive lock on a file between processes, held for a `with` block and let go when the process ends, crashing too: a module checks for something and makes it inside one, so two calls at once never make two; with `wait=False` a lock another holds raises `Held` at once. The intake's `intake.lock` in the project's home folder shows it. `metaform.data` offers `query_reads()` to list named reads and `query_read(store, name, arguments)` to run one with its existing text argument conversions. `Record` supports module-defined records, `plain(value)` converts nested records to JSON-ready data, and `NewerStore` identifies a store requiring newer code. `metaform.outline.markdown(store, address=None, selection=None, raw=False)`, `metaform.outline.mermaid(store, address=None, direction='TB', leave_out=(), selection=None, raw=False)` and `metaform.finish_xml.xml(store, address=None, selection=None, raw=False)` are the shared map document writers. The map command and web export use them directly so each format has one implementation, BASE-004, MAP-052, MAP-059 and VIEW-024. `metaform.module.node_brief(folder, address)` is a node's brief as an agent reads it at `metaform://<address>`, the map module's own `where` read, which the MCP server serves and the web GUI shows, MCP-037; `metaform.module.mcp_reads(folder, uris)` reads the folder's own MCP server over MCP as an agent connecting to it does, its connect instructions, its tools and each resource named, for a surface that shows the person what an agent receives. Hello's `basedemo` shows the shared reads and removal preview, `base-restore` and `base-remove` show the project actions, and its existing `follow` shows `Context.listen`.

A module that reports the state of work, a run, a ticket or a session, uses `metaform.data.status`, so every module reports one set mapped to MCP Tasks and A2A, for example `status.moved(row['state'], 'cancelled', next_step)` before it writes the new state, then `status.MCP_TASKS['cancelled']`. The workflow module's `runs.py` shows it.

`metaform.module.code_print()` returns a fingerprint of the package's Python source paths, modification times and sizes on disk, using metadata only and creating no state. Long-running modules compare it with their startup fingerprint when a store requires newer code, so unchanged code does not cause replacement loops. A changed fingerprint does not prove that a replacement can open the store. It works with installed and editable packages. Hello's `basedemo` returns it as `code_print`.

### Provides

What the module offers other modules, `MODULE.provides`: each a `Provides(kind, value)` of `metaform.module`, found by kind with `metaform.module.provided(folder, kind)`, every enabled module's in module id order, so neither module imports the other and turning one off withdraws what it offered. The kinds in use: `voice.engine`, a `VoiceEngine(name, summary, sends=, transcribe=, speak=, ready=, formats=)` the voice module offers as a choice beside its own engines, where `sends` says plainly where the person's audio or text goes, `transcribe(ctx, path, language)` returns `{'text', 'segments'}`, `speak(ctx, text, character, format)` returns an iterator of audio chunks and `ready(ctx)` is None or why not, the elevenlabs module's showing it; and `voice`, the voice module's own `speak`, `transcribe` and `transcribe_stream` for a server-side caller such as a phone bridge. The template provides nothing.

## Prompts

Universal skills use `metaform.skills`, BASE-059. Each authored folder under
`metaform/skills/<name>/` has Agent Skills frontmatter in `SKILL.md` and its
procedure in `references/procedure.axiom`. `catalog()` reads the metadata,
`listing(discoverable=True)` omits internal skills, `load(name_or_address)`
returns the procedure with current prompt-store libraries, and `read(name, path)`
reads one skill file. The `ing.metaform.*` metadata declares its Address,
discoverability, version, tier and required libraries. Keep procedures in these
folders so native deployment, MCP and Axiom calls use one source.

The prompts in `resources/prompts.xml`, each an element named for the prompt, and where each is served, MCP-031. A prompt the module sends to an agent is read with `prompt_files.served(resources.files(__name__), name, **fills)` rather than `required`: the home's prompt store keeps it as `<module>:<name>`, the shipped text becoming a version whenever it changes, and an edit saved there (with `metaform agents override`, or `metaform prompts review`) is sent in its place, STORE-044; a shipped change that lands while an edit is sent is kept beside the edit and shown on the agents module's role, `prompts.behind(name)`. Fill places are empty elements, as for `required`, and a prompt on trial (`METAFORM_PROMPTS`) is read first and never stored. A runner that wants to know which versions each turn carried starts `prompt_files.collect()`, takes the `Sent` records from the list as each turn goes, and lets go with `prompt_files.release(list)`; dispatch's runner does, and tells them on `prompt.sent`. A module whose prompt a role is sent is named on that role in the agents module (`ROLES`), so the person sees it there. `instructions` is listed in the instructions agents read under "modules available."; a copy writes its own module name in place of `template`. `prompt_files.module_commands(id)` reads a loaded module's declared slash commands through the public base, returning an empty list when the module is not found.

`rules` holds the module's rules, MCP-031: `<rule why="the reason">One sentence.</rule>` each, a rule an agent keeps while it works with the module and the reason it holds. The MCP server delivers a module’s rules with its first command use in a retained context; discovery lists the module’s commands without repeating those rules. A rule without a why stops the module loading. The template's is empty; memory's shows one.

## Verbs

Each verb, what it returns, and its CLI form `metaform <id> <verb>` and tool form `<id>_<verb>`, and its `effect`, `read`, `write` or `remove`, with `open_world` when it reaches agents or the network; the MCP server gives them to hosts as the tool's annotations. Mark a verb that can take long `task=True`: an AI tool that declares the MCP tasks extension is answered with a task it polls, and every other caller waits as before, BASE-030; hello's `wait` shows it. A cancel stops an `async` verb at its next `await`; a verb run in a thread finishes, and its task completes with its result, so a task never reads cancelled while its effect lands. A verb that returns `{'run': <run id>}`, a workflow run record the server itself advances to its end, such as an agent Metaform starts and steers, is marked `task='run'`: it runs as ever, and that run is the task, followed until it ends. A task only for work the server advances by itself: a host gives the model a task's result only once it ends, so a verb whose result the calling agent must act on, such as workflow's `assign`, is marked neither. A verb's `caution` is put to the person in their AI tool where it can show a form, so the agent does not answer for them, MCP-006. A verb that is the person's decision, never an agent's, such as one that clears, switches or removes what every agent sees or deletes what agents recorded, declares `person_says=True` with its caution: it runs only on the person's own yes, `--confirm` at their own terminal, the page, the form their AI tool shows them, or the consent card in a dispatched agent's chat; an agent's `confirm`, or `--confirm` from a command an agent runs, is refused with the caution, told to ask the person in chat, and given the command the person pastes (`metaform.module.persons_decision`), and its tool is marked destructive, CLI-011. Name the page's control that does the same with `page=`, such as `'the base picker'`. Give it `cautioned`, a function of the call's Context returning the caution with what this call would take, counted: a base's `metaform.module.base_holds(project, base)` adds up what each module counts of a base by `Provides('base.holds', count)`, `count(store)` returning counts by kind (`tickets`, `layers`, `conversations`, `agents`). `metaform.module.agent_caller()` says why a process does not carry the person's consent, or None when it does: it runs at the person's own terminal with no agent above it, or the web server ran it for a write from its own page. Nothing else, no environment and no parent, gives a process the person's authority (`metaform.caller`). A verb that is the person's decision only for some calls, by what they ask, declares `person_decides`, a function of the call's Context returning the caution when this call is theirs and None when it is not, such as `map work` releasing a held ticket or `dispatch start` starting one: such a call runs only on the person's consent, through the same channels, with no `--confirm` at their own terminal, and an agent's is refused with the caution and the command the person runs, or, for a dispatched agent over MCP, waits on the consent card in its chat. It reads only the record the call names, so a call it does not concern costs nothing. A verb that works where no project is registered declares `needs_project=False`: over MCP it is listed from the start and takes no `project`; the rest are listed once the folder is registered, announced as a list change. A verb whose result follows the map's layers turned on declares `reads_layers=True`, and only its tool takes the per-call `layers` argument, MCP-003. Each verb is discovered under its declaring module at `metaform://<id>/tools`; no category assignment is required or supported. What a verb's details say only to the person and the agents that act for them, such as how the person writes a record, goes in `person_details=`: the command line's help shows it after the details, and over MCP only the person's own sessions, the system agent and a sentinel are given it.

## Settings

Each setting the module declares, its default, and which verbs read it as a switch. A value is a setting only when a person would sensibly choose it differently and the choice changes what the module does; each other kind of value has its own home (settings cleanup, 2026-10-15). A value with one right answer is a named constant beside the code that uses it, with its reason in a comment. How the person's page looks right now is view state, kept by the module that draws it (the web module's `view.py`), never a setting. A set of records, such as peers or pins, is kept by the module with `add` and `remove` verbs, never as one list setting, since storing such a list replaces every entry at once. Values that belong to one name each, such as each agent's, are one setting for each name (`dispatch_<agent>_strengths`), never a `<name>=<value>` list, for the same reason. A module that removes, merges or reshapes a stored setting carries its stored values over once from its `start` hook with `metaform.settings.carry_once(step, carry)`: `carry()` moves the rows through `metaform.home.stored`, `save`, `clear` and `set_glue` and returns what it said, and the home's meta records `carried:<step>`, so the carry runs once per home, under a lock, without a marker file. A setting declares `section='Heading/Subheading'` to sit in a menu of its own on the settings screen and the TUI, and `choice_help={choice: plain words}` (or a function of a Context) to say what each choice does. A select whose choices let an agent act without asking declares them as `risky=('approve-all',)` (or a function of a Context): every surface asks the person to confirm one before it is stored (`metaform set ... --confirm`, `confirm` on the agent's set tool, a yes on the settings screen and the page), and stepping through the choices never lands on one. A value that has a known set declares `choices`, a list or a function of a Context that reads them from their source. A list with choices refuses a member outside them on every surface, unless it declares `beyond_choices=True` and its `check` says what another member does. A select whose choices come only from starting something, such as an agent's models, declares `choices_from=` with the command that reads them; the settings screens offer to run it while the select offers no more than its default, and a refused value names it as the next step. A setting declares `category=` (one of `metaform.settings.CATEGORY_NAMES`) for its page on the settings screen, or takes the module's `settings_category`, else advanced; `heading=` for the small heading it sits under there, which, unlike a section, opens no menu in the TUI; `essential=<n>` for a place on the Essentials page the screen opens on, kept for what a person needs to set Metaform up and run it day to day; `unit=` for what a number counts; and a plain `label=`, since the default is the key in words. A switch whose stored value would silently change later calls of another kind, such as a transport or a dry run, declares `per_call=True`: it is given on the verbs that list it in `switches` and never stored, so `set` refuses it and the settings screen, `config --show` and the agent's set tool leave it out.

## Events

The install stage publishes `install.completed` after committing a successful newer installation, with `version` and `wheel` in the payload. Subscribe with `Subscription('install.completed', handler)` when a module needs release upkeep. Reinstalls, downgrades and failed installs do not publish it. Direct wheels deliver the follow-up through setup handover to the installed process, whose dependency environment can run upkeep agents. Fork's subscriber compares templates in registered module repositories and retains manual upkeep for retries, BASE-027 and BASE-047.

The topics the module publishes and those it subscribes to. After any command that changes a project's map, the chassis fires `map.changed` with `project` and `base_id`, no id meaning the project's bases changed, and the web server does the same after the page's own writes; a module does nothing to announce its writes, and any module can subscribe to it, as the web module does to redraw its open pages, VIEW-018. The chassis fires it when the command ends, so writes a module makes outside a command, in a task it spawned, and writes made inside a verb that runs on for a long time, such as `dispatch run` or a server run in the foreground, reach an open web GUI while it runs only when the module publishes `map.changed` itself after each write, with the project and the id of the metaform it wrote to: `ctx.publish('map.changed', {'project': ..., 'metaform_id': ...})`, or `await ctx.publish_async(...)` from a coroutine. The chassis still fires it once for the command when the command ends. dispatch's runner shows it, publishing after each write it makes. A module whose own process runs on, such as a server or a runner, hears `map.changed` published in other processes with `listener = ctx.listen(handler)`, BASE-053: the handler gets each payload in the listener's own thread, so code on a loop hands it over with `loop.call_soon_threadsafe`, and `listener.close()` ends it. Its own process's changes reach it through its own code, not the listener. hello's `follow` shows it. Nothing polls for a change, and nothing a person or an agent waits on blocks behind slow work, QUAL-015.

dispatch's runner publishes `prompt.sent` as each turn of an agent session goes that carried a prompt: `project`, `work_id`, `session_id`, `runner`, `role`, `agent`, `at` and `prompts`, each `name`, `number`, `origin` and `version_id`; the agents module keeps them. A module that sends a session's turns itself publishes the same topic.

When a feature the person has set up stops working, such as a number pointed where nothing answers, raise it to the person's system agent rather than printing it or putting it on the page: `ctx.publish('signal.raised', {'signal': 'setup-not-working', 'module': <id>, 'key': <a fingerprint of the findings>, 'feature': <the feature in words>, 'set_up': <what the person set up, in words>, 'look': <the tools and commands that read it>, 'report': <the findings>})`. dispatch keeps it, and the person's system agent takes it as its next turn, `<setup_trouble>` in dispatch's prompts.xml, and brings it up with them; while none runs, the page offers one small notice that starts it. Publish the same with `'clear': True` and the same `key` once the findings are gone. Raise each set of findings once and decide yourself when to raise it again; twilio's `troubled` shows it.

When something a module runs fails in a way no one expected, publish it as a fault, so autoticket files it as a ticket to fix: `ctx.publish('fault.raised', {'source': <a word for what raised it>, 'message': <the one line saying what failed>, 'detail': <a traceback or the text seen>, 'file': <the failing file, when known>, 'reproduce': <how to make it happen again>, 'work_id': <the ticket of the agent whose call failed, when one did>, 'count': <how many, when repeats were merged before sending>})`, or `await ctx.publish_async(...)` from a coroutine. Only `message` is required. A refusal the module meant (a `Stop`) is no fault. autoticket groups repeats of one kind into one ticket and caps how many it keeps open, so publish each time it happens; the web server, the page, the MCP server and dispatch's runner do.

## Authored roles and delivered context

Contribute `AgentRoleDefinition(name, purpose, prompts)` values as `Provides('agent.roles', definitions)`.
Definitions describe reusable expertise; task IDs, objectives and return destinations belong to assignments.
`specialist=True` is the default. Set `specialist=False` for framework duties such as triage or generic implementation;
these are excluded from automatic specialist matching. `agents_specialists` lists names, purposes and role URLs
without loading duties. JEV chooses from that inventory, and unresolved tickets go to triage for selection or creation.
Each prompt is its existing prompt-store identity, in delivery order. `metaform agents resolve name=<name>`
and `metaform://role/<name>` resolve the definition through the enabled provider and its owning renderer.
An authored role is a responsibility separate from the operational `METAFORM_ROLE`; inspection changes no binding.
The hello module contributes `hello.greeter`; the template keeps an empty declaration.

`Provides('prompt.render', renderer)` supplies owning-module bindings as `renderer(ctx, component, bindings)`.
The resolver then renders the actual selected prompt-store version and reports a fallback separately. Generated
duties may be stored without an XML element through the `agent.role` service used by the GC's Role Creator.

`prepare_agent_context(folder, session, components)` selects exact component bodies still due in the current
epoch. `record_agent_context` acknowledges only bodies handed to the harness; rendering and queuing do not
acknowledge them. `advance_agent_context` is for completed compaction or recovery without retained context.
Both inline turns and a worker's separate MCP process use the same recipient identity and persistent ledger.
A module returning knowledge can use `ctx.queue_context(components, epoch)`, with each component's exact
`delivered_value`; MCP records only complete bodies that survive response shaping.
`Count.revisions` identifies changed entries whose totals stayed the same, and `Count.updated` counts updated
unread bodies without changing the existing total/new/mine tuple.

`collecting_agent_context(session)` establishes the transport's shared receipt collector and recipient identity.
Nested node and item hooks inherit it even when their own context has a default CLI surface;
`agent_context_collecting()` tells a producer to defer acknowledgment to that transport. A shaped response commits
only its exact surviving `delivered_value`, and a receipt prepared before an epoch advance cannot acknowledge the
replacement context. `prompt_files.resolve` and `resolve_text` inspect the actual selected text and version without
recording delivery; `Sent.rendered_text` retains the exact body for a later transport handoff.

Requested source changes are listed by existing identity in the shipped `resources/prompt_updates.json` manifest.
`prompt_files.merge_selected_updates(name)` applies each unique old anchor to the selected version atomically,
appending a version with that selection as its parent. An ambiguous or unmatched edit remains selected and reports
a nonfatal conflict; later explicit user edits remain authoritative. `metaform agents updates` reads the source,
before/after versions and outcome. Whole skill procedures and legacy library sections retain their existing prompt
identities, and skill reads and deployment use the selected procedure and library versions.


## Project background services

`Provides('project.background', start)` exposes an event-driven service owned by the web supervisor. `start(ctx)` returns an object with `close()`, or `None` when its policy disables it. One instance runs per registered project even with no page open. Module/chassis settings changes refresh it; shutdown closes it. `close()` must release listeners, native watchers and leases. Do not poll for changes or react to unrelated events. Publish failures on `fault.raised`; bounded failure backoff is allowed. A service that has `heard(payload)` is handed each `map.changed` of its project by the web server that holds it, the server's own writes and those of other processes alike, so it hears through any reload of its module and opens no listener of its own; it decides from the event alone whether the change concerns it. Autoticket supplies the built-in supervised log watcher through this contract.

`Store.context(address).knowledge` contains explicitly scoped CEL content with layer, source and attachment provenance. An item inherits only when `extra.instruction` is true. Ordinary evidence remains local. Context selection and masks apply before delivery; functional joins retain their own receivers.

## MCP discovery

A module publishes its capability through `Module.id` and `Module.summary`. Agents discover active modules and their descriptions at `metaform://modules`, then read `metaform://<id>/tools` for the commands belonging to that module. MCP tool names are `<id>_<verb>`; their arguments come from each verb's `Noun` declarations. No central category table or `Verb.category` is involved. Settings-screen categories remain independent.

Reading a module's tools resource selects that module for the caller's session. `metaform_catalog module=<id>` does the same. Startup lists only discovery, and stateless clients invoke commands with `metaform_catalog tool=<name> arguments={...}`. `metaform_catalog search=<words>` tolerates misspellings; `module=<id>` can narrow the search. Search results identify the owning module and do not execute commands.

Disabled, withheld, unsupported and dynamically unlisted commands follow the existing surface rules. Module rules accompany the first command invocation. Directory and module-resource reads share content receipts with catalog calls; unchanged text stays suppressed until context recovery.
