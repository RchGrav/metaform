# Changelog

Each change to the module, newest first.

## Unreleased

- 2026-10-21, ticket code.system.management.knowledge#92: finished results go directly to the page, including every topic's synthesis, Borda order and points, final answer and saved transcript links. Status retains the same topics for revisits. Removed the system-agent report request, its inbox wake and report-writing prompts. `report=true` reads the engine's saved mechanical transcript.

- 2026-10-19, the question is the frame and the report is the outcome. `open`'s Address is optional, `open <topic> [address=]`: with none, the opening is the new prompt `opening_question`, the question alone, limited to no part and to no project, and the seats read the project's files when the question touches it; with one, the opening is the part's context as before. When a table ends, its record (`export.json`, `mechanical-report.md`) is saved and handed once to the person's system agent as a project update of kind `roundtable_report` (new prompt `report_request`), which its inbox names and which starts its turn (dispatch's `inbox_wakes`): the agent reads the record on demand, writes `report.md` beside it, and shows the person a link and a few lines. The engine's reporter seat no longer writes Metaform's report: `open`'s `reporter` noun, the saved engine `report.md`, the `report` and `report_error` columns and the prompt `outcome_unreported` are deleted; `status` shows `report`, the system agent's file once written (`report_text` with `report=true`), and `handed`. The outcome memory cites the record, prompts `outcome_record` and `outcome_report`, and a table with no part keeps it at the project's top element. `adopt` on a table with no part files its ticket at `address` when the map holds it, else at the top element with the Address in its note (prompts `adopted_note_question`, `adopted_proposed`); the map is never changed. The page's T key opens a table with no selection, focused on the selected part when there is one; the server's `/api/roundtable-open` takes no Address. Tables at version 2: `address` may be empty; `reporter`, `report` and `report_error` are dropped.
- 2026-10-19, ticket d79d84b5 (code.interface.graphical#131), for the page's roundtable stage: `open`'s `seats` may be left out for the new person's setting `roundtables_seats` (Claude's opus, sonnet and haiku by default); a table's host is its first seat when none is named, where the engine's default seated Codex unasked; `status` gives `seated`, the seats' names at the table; and each write of a follower names its table as a kind too, `roundtables:<table>`.
- 2026-10-19, ticket 34c33d69, functional assessment 69ebe376: a table's slots last as long as its seats. Stop all asks a table's follower to stop with SIGTERM (dispatch's new `stopped_seats`) instead of killing its group, and a removal of the project does the same, while a metaform's clear leaves the table be; the follower, on SIGTERM, SIGHUP, an error or its page server failing, tells the person (`operational`, `follower_stopped`), ends the table through its page server and follows it until the engine has closed its seats, and only then gives the slots back. A stream that says the engine no longer holds the table is told as its `end`. Any failure while opening refuses the table with the error at once, and a table the engine opened before it, found by the id its engine subject now starts with, is ended. `open` says when its follower ended without a word, not that it was silent. An ended table's last unjudged submission is told as a `turn` with outcome `unjudged`. The tables snapshot holds the module's tables.
- 2026-10-19, ticket 60af03de (code.store.memory#d): a table's answer is kept where it was asked. When a table ends its follower saves the engine's report, mechanical report and JSON export (with the Borda count) in the project under `docs/roundtables/<n>-<topic>/`, and records one memory at the table's Address through memory's new `memory.record`: the question, the host's answer, the top three ideas by the Borda count, each seat's explanation of its top three, and the saved report, which it cites. `status` shows `saved` and `recorded`; the `end` event carries them. New verb `adopt <table> <idea> [address=] [title=]`, the person's decision: the idea becomes one ticket at the part it concerns, its note naming the table as its source, which Full Auto starts like any ticket, kept as the table's `adopted` event so a second adopt gives the same ticket. Prompts `outcome_*` and `adopted*`. No table change. After functional assessment f5ec55f8: a table that ends with no report still has its outcome recorded, citing the saved `export.json`, with the new prompt `outcome_unreported`, where before memory refused the whole memory for citing a `report.md` that was not saved; an adopted idea's ticket names `export.json` the same way; and `adopt` passes on the map's notices, such as an `address` with no current element.
- 2026-10-19, ticket 34c33d69 (code.gateway.messaging#3), the module: a table opened on a question at an Address through the person's Roundtable 2 engine, the part's context from the map as its opening, seats of Metaform's agents and OpenRouter models; the chair's controls; a follower per table turning its changes into `roundtables.event` and project-level event rows announced as `map.changed` of kind `roundtables`; the report and the answer saved at its end. Each seat holds one of dispatch's agent slots, through dispatch's new `dispatch.seats`. Tables at version 1: `tables`, `events`, both at the project's place. Named `roundtables` because this project's `modules/roundtable.sqlite3` still holds table 1's record from the module of that name that moved to its own server on 2026-10-14.
