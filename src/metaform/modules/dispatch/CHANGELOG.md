# Changelog

Each change to the dispatch module, newest first.

## Unreleased

- `serve` after its second review, BASE-062: a response Metaform takes in holds the agent's next line until it is passed on, so the editor hears the agent's order (a session's id before its updates); `session/delete` is forwarded and keeps the session out of Metaform's list pages (an `unlisted` line `threaded` leaves out), and is answered alone; `session/fork` gains the server, the commands and a record as `session/new` does; a page message is steered into the turn in flight with `_session/steering` as the runner's is, and the reply says `steered`; the list carries the agent's `session_info_update` title and last activity and the session's `additionalDirectories`; updates heard before a session's record exists are recorded once it does; a cancel read before any wait; `message`, `interrupt` and `stop` without `session=` take the latest session that is running still, and a session that stops answering is a Stop; `session_status` keeps an editor session running on a late reply; new prompts `serve_commands`, `serve_alone_title`, `serve_alone_notice`, `serve_server_title`, and `serve_free_text` says `/` lists the commands only while they are offered.
- `serve` after review, BASE-062: a terminal login method's `args` move into its `env` as `METAFORM_SERVE_LOGIN`, and serve started with it becomes the adapter with those arguments, so an editor's Login works through Metaform; agent updates reach the editor before they are recorded, the record written in order by one task per session; every turn holds the session's lock, so the page's and the editor's prompts never overlap, and the editor's cancel answers a waiting prompt `cancelled`; `message` takes `session=<id>` as `interrupt` does, both checked live, and the page sends it; editor sessions take no slot in autostart or summoning; `stop` fails with the session's own error; `session/list` lists only what the agent can open, filters by the recorded `cwd` (every project without one) and chains Metaform's cursors after the agent's; alone, `initialize` is ACP v1 as published with `close`; Session Notices, `messageId` on Metaform's messages and `$/cancel_request`; a steered message from another agent shows as theirs; the state line keeps only the agent's commands.
- Editors mount Metaform, BASE-062: `serve` speaks ACP v1 as the editor's agent over stdio, a transparent proxy to the agent behind it that adds Metaform's MCP server, lists the dispatch sessions of that agent, offers Metaform's MCP tools as slash commands answered with no turn, and records the session on the held ticket "Sessions from editors" with a control port the page messages and interrupts; with no agent, a model-free agent that answers its commands and lists and replays dispatch sessions. `runner_of` names a `dispatch serve` process `SERVED`; `anchor` takes the held ticket's task, and gives it its title. New settings `dispatch_serve_agent`, `dispatch_serve_commands`, `dispatch_serve_record`; new prompt `serve_free_text`. The Proxy Chains and MCP-over-ACP RFDs are drafts the SDK and adapters do not implement, so neither is used yet.
- The ACP harness after its second review, Phase 2:
  - Elicitation forms as the adapters send them: a choice field with a free-text companion (claude-agent-acp's `question_<n>_custom` "Other", codex-acp's note named by `_meta.codex.questionId`, or any optional string beside the only choice field) is one question; its choices are the suggestions, a bare choice fills the choice field, other words the companion, a choice and words both. An answer that fills no field is asked again, never an empty accept. Limits (length, pattern, format, range, count) are checked and defaults filled. A field `_meta` marks secret is never asked at the node or kept in the thread. The question keeps its session, tool call and subagent, and a `_meta` `autoResolutionMs` shows as its deadline.
  - Request cancellation: the agent's `$/cancel_request` for a waiting question or permission request closes it at the node, clears its signal, marks it `withdrawn`, answers -32800 and lets the silence clock run again; `elicitation/complete` closes a page question still waiting.
  - Spend: during a turn a provisional token estimate from each `usage_update` `used` is held against the token budgets, so `interrupt` can stop a runaway turn part way; cost acts at the turn's end, each currency on its own (`costs`); a cost before the first prompt is the baseline; `unmetered` is per measure, and `spend` notes an agent that reports no cost while a cost budget is set; `tokens` is called an estimate.
  - The hand-off's links go as ACP `resource_link` blocks too, and the ticket's item as `metaform://<address>/items/<n>`.
  - The status a runner gives says `waiting_on`, question or permission.
  - `<record>` is back to the approved wording.
- The ACP harness after review, Phase 2:
  - ACP elicitation, Completed 2026-07-22: the runner advertises `clientCapabilities.elicitation` in both modes and answers `elicitation/create`. A form is asked at the ticket's node and on the page, its lone field's choices as suggestions, the answer checked against its schema and sent as accept with content, decline or cancel; a URL is shown with its host, never opened or fetched by Metaform, and accept is the person's consent; `elicitation/complete` marks its line. New `elicitation` lines and `question-waiting` signal; `permit` answers a question too; new person-only setting `dispatch_elicitation` (`ask`, `decline`). dispatch_prompts never answers a question.
  - Session notices, Completed 2026-10-09: `clientCapabilities.session.notices` advertised; each `notice` is an `agent_notice` line, live only.
  - Spend in billable units: `spend` rows keep input, output, cache read, cache write and thought tokens apart, `tokens` their billable sum (cache reads at a tenth), the cost each usage update added rather than the session's running total, and `metered`; `dispatch spend` names `unmetered` sessions. New budgets `dispatch_budget_cost_ticket` and `dispatch_budget_cost_day`, checked on each cost report during a turn, and `dispatch_budget_action` (`signal`, `interrupt`). Every budget ships at 0, off, until the person sets the numbers. A retry spends against the run of the session it resumes, its new `run` noun.
  - Cancel is the person's and leaves a terminal state: effect `remove`; refused over MCP while `agents_may_set_control` is off, as `tune` is; the ticket closes with the map's work `outcome` `cancelled`, so the list, the ticket read and `wait until=done` say cancelled; the `outcomes` table is gone. `tune` refuses a value the ticket's agent did not offer, and the ticket read shows the ticket's own `options`.
  - The silence clock starts again on every update while a turn is in flight, so a turn silent twice is signalled twice; `dispatch_silence_minutes` becomes `dispatch_silence_seconds`, 300 by default.
  - The hand-off is the work line, the owner's sentence on recording at the node while memory is on, the ticket's fields, the OP and EF of the joins its node receives, the node's brief with its reads named as MCP calls, and `metaform://` links of the node and the ticket's item. `<work_record>` holds the owner's sentence with the node filled in, a draft placement awaiting his approval; `<retry>` is marked a draft.
  - Lifecycle: options are applied mode, model, model_config, thought_level first; a resume or load that names no settings leaves the catalog's; an ending session sends `session/close`; `options prime=true` deletes its throwaway session with `session/delete`; a steer unanswered in 10 s is withdrawn with `$/cancel_request` and not sent again; `login` asks as a terminal-capable client, refuses a terminal method without a terminal, and checks the login took; a session whose agent needs a login is handed over with no retry; initialize falls back to the SDK's own call when its JSON-RPC connection is not there.
  - `dispatch_agent_options` declares `exclusive='='`, one value per agent and setting on the settings screen and in the TUI.
  - Tables version 11: `spend` gains its columns, `outcomes` is gone.
- The ACP harness in full, Phase 2:
  - The hand-off is the node brief plus one sentence, the `work` prompt: work the ticket with the `map_work` tool and record what you learn with memory at its node. How to work a ticket moved to the `map_work` tool's description and its `op` and `said` arguments. The 4.4 KB `handoff` brief is no longer sent; `handoff id=<id> full=true` reads it. The `nodes` line is gone.
  - Option discovery, P199 and P015: what `session/new`, `session/load` and `session/resume` answer is kept per agent and version in the new `catalog` table and offered as the choices of the new person-only setting `dispatch_agent_options` (`<agent>.<category or id>=<value>`), applied to every session with `session/set_config_option` or `session/set_mode`; `tune <id> model= effort=` sets a ticket's own, kept in `ticket_options`; `options [agent=] [prime=true]` lists the catalog, or primes it by starting the agent with no prompt.
  - Lifecycle: the agent's stderr is piped into `stderr` lines, batched, redacted and capped by `dispatch_stderr_kb`, its tail on failure notes, P014; a per-turn silence clock raises `silent` after `dispatch_silence_minutes`, paused while a permission waits, P040; a message to a turn in flight is steered into it with `_session/steering` when the agent advertises it and `dispatch_steering` is on, P016; subagent sessions are child sessions with threads of their own, read under `subagents`, P016; `_auth/status_update` and an `auth_required` answer raise `login-needed`, and `login <agent>` runs ACP `authenticate` or the agent's terminal login, P031; `cancel <id>` sends `session/cancel`, ends the session and records the ticket cancelled in `outcomes`, P232.
  - Supervisor and budgets, P012 and M01: `autostart` resumes a worker's session that stopped without the person's stop, after `dispatch_retry_seconds` doubled per retry, up to `dispatch_retries`, then hands it over with `handed-over`; each turn's tokens go to the `spend` table, and `dispatch_budget_ticket`, `_run` and `_day` are checked before every start, retry and next glyph ticket, raising `budget`; `spend` reads them.
  - Identity: the server the runner asks for keeps the name `metaform` and its env names `METAFORM_HOME` and the session's identity; `DISABLE_MCP_CONFIG_FILTERING` keeps Codex from dropping it for a configured server of the same name, ticket 80cafcd9.
  - Tables version 10 adds `catalog`, `ticket_options`, `spend`, `attempts` and `outcomes`; version 5's code still reads and writes the tables.

- The hand-off informs and does not dump, MCP-039: the first turn and `handoff id=<work id>` are the `handoff` prompt, then the `nodes` line, the ticket's fields, its node in one line with its OP and EF, its linked nodes by address and the counts at its node and around it with the calls that read them. The indented JSON of every where read is gone: at this project's busiest node the hand-off fell from 18,231 bytes to 5,998, of which 4,392 are the brief. The counts are told once to the agent's session, the runner's `METAFORM_SESSION`.
- No nonces, BASE-050: an agent dispatch starts over ACP is given its work by the session itself, the hand-off as its first prompt and `METAFORM_ROLE`, `METAFORM_SESSION`, `METAFORM_WORK` and `METAFORM_NODE` for its MCP server, so the runner requests no nonce. `handoff id=<work id>` prints the ticket's hand-off prompt and its nodes for the agent the work is handed to by id; the `handed` prompt is gone. The intake's text waits in its launch's `raised` row, the new `asked` column, which the runner reads and clears before its session is made; `run` no longer takes `asked`. Recovery evidence is the session row's private `recovery` column. Tables version 9 adds both columns, which may be empty, so version 5's code still reads and writes the tables; `nonce` stays in `sessions` for rows written before and is no longer written.
- Record on finish, BASE-052: the new setting `dispatch_record_on_finish` (off, when-missing, always; `when-missing` by default) gives a worker whose ticket is done one more turn, the `on_ticket_done` prompt, before its session ends, when its session wrote no memory join or observation at the ticket's node, told by `by` against the session's `runner`. `on_ticket_done` ships empty until its wording is written, and empty sends nothing. The memory module is read through its `joins` and `graph` verbs, `memory_read`, without importing it. The fake agent's `done` mode records a memory first with `FAKE_ACP_RECORD`.
- The queue moves without the page, VIEW-042 and BASE-052: a runner that has finished its sessions runs `autostart` in its own process, which recovers dead runners first and starts nothing when Autostart agents is unchecked. `autostart` counts free slots and reserves the tickets that fill them in one write transaction on the work store, so the page's check and a runner's never fill one slot twice; the runners start after it commits, through `run_reserved`, which `start` uses too.
- Steering goes by role, BASE-052 and MAP-050: `start`, `stop`, `message`, `interrupt`, `resume`, `configure` and `permit` refuse an agent whose role the person's `roles_without_authority` names, `worker` and `prep` by default, on the CLI and over MCP; the page is never refused. A message an agent sends is a `message` line, `From the <role> agent: …`, and no longer a `person` line.
- `wait until=done|stopped|signal [id=] [since=]`, BASE-052: an orchestrator blocks until a ticket is done, its agent stopped with it open, or a signal is raised on it, for at most the new setting `dispatch_wait_seconds`, 50 by default, and gets `pending` with the next call at the limit. With no id it waits on every ticket of the project and names which woke it. It wakes on `map.changed` through `ctx.listen`, never on a timer, QUAL-015.
- ACP used to its fullest for the page, BASE-052 and VIEW-039: the agent's capabilities, settings (its modes and config options, a model among them), slash commands, plan, usage and the parts of the map it touched are the session's `state` line; each tool call's diffs, locations and terminals are a `tool_detail` line, each file placed on the map through the `sources` layer's refs; each permission request is a `permission` line with its options. `sessions` returns the states under `states` and each structured line's JSON as `data`. New verbs: `agents` lists the agents with whether each start command is found and the default; `intake` starts an agent on the project's intake, VIEW-045; `resume` resumes an ended session in place through `session/resume` or `session/load`; `permit` and `configure`, CLI only, answer a permission request and set a session's mode or model. `start` no longer makes the agent it started the default, and `system` uses the default agent. The fake agent offers modes, a model option, commands, an edit and `session/load` when asked.
- One agent per glyph, VIEW-040: a runner started on a ticket with an agent glyph works the glyph's tickets one after another in board order, a session for each, the next taken when the one before is done; `start` and `run` refuse a ticket whose glyph's agent is at work and name the ticket it works. The glyph is read through the base's `work_reads`. The fake agent names each process's session by the sessions made before it, and its `done` mode closes the ticket its prompt names.
- The runner hears `map.changed` from other processes through the base's listener, `ctx.listen`, BASE-053. dispatch's `map.changed` subscriber, `relayed`, `RUNNER` and the control port's `changed` request are gone; the port takes `message` and `stop`.
- A question a dispatched agent asks itself with `map ask` is told to it when the person answers it, as the `answered` prompt, BASE-052. The runner knows the question by its id in the output of one of the agent's own tool calls, made no earlier than that call began.
- A ticket's sessions show on its work record, BASE-035: dispatch's `work_read` adds `{"sessions": [...]}` under `dispatch` in `metaform map work id=<id>`, each session from dispatch's own table without what only reaches a running session.
- dispatch reads its prompts with `metaform.prompt_files`, now part of the public base, BASE-004 and MCP-031, and no longer carries its own copy of the reader.
- dispatch is made from the template at its changelog's Unreleased contract, BASE-019 and BASE-052: `start`, `run`, `message`, `stop` and `handoff`, the `dispatch_claude`, `dispatch_codex` and `dispatch_gemini` settings, the `dispatch` layer, and a `map.changed` subscriber.
