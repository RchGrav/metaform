# Changelog

## A session is its task: METAFORM_TASK_NAME replaces METAFORM_ROLE (2026-10-25, the owner's decision)

- The runner of a task session gives its agent's MCP server `METAFORM_TASK_NAME`, the task's name (`user_agent`, `project_agent`, `composer`, `facilitator`, `architect`, `intake`), beside `METAFORM_TASK`; a session no task names, a ticket's agent started with `dispatch start`, a talk or a helper, carries no such name, and its first turn is its instructions. `METAFORM_ROLE` is gone from every identity list and reader; whether an agent runs a command is read from `METAFORM_SESSION`. A message or a stop an agent sends is named by its task (`From the composer agent: …`; `From an agent: …` for a session no task names). The MCP server's instruction block `metaform://role/<role>` is `metaform://task/<name>`, linked to the person's own session (`person`) and the intake task (`intake`) alone; the prompt elements `role_worker`, `role_prep`, `role_talk` and `role_system` are gone, `role_intake` is `task_intake`. The runner's own `role` word stays internal launch plumbing and reaches no agent.

## The intake's guards are removed (2026-10-25, the owner's decision)

- An intake agent is started and told its task; nothing times it, steers it or withholds tools from it. Removed: the first-record clock and its one steer (`intake_clock`, `first_record_due`, the `intake_first_record` prompt, the setting `dispatch_intake_first_record`); the withheld tools (the setting `dispatch_intake_withheld`, `METAFORM_WITHHELD`, `module.withheld`, the `intake-conclusions` signal and `intake_call`); the session's `intake` state (`starting`, `waiting for first record`, `recording`, `first_call_s`, `first_record_s`), its `phase` in the control reply and in `dispatch sessions`, and the page's reading of it. The role `intake`, the one-intake-at-a-time hold and the launch and recording paths stay. The server lists every tool to every agent.

## Local integration preserves dirty checkout edits (2026-10-21, code.scheduler.task#55 with code.dispatcher.agent#10)

- `merge.advance` integrates beside existing checkout edits. Clean paths take the integrated content. Modified paths receive its hunks through a three-way merge in the working copy and, when staged, their index entries. Conflicting local paths remain unchanged and appear in one board-needs notice for the system agent. The ticket stays closed in every case. Previously, local edits in touched files failed integration with `Entry ... not uptodate`.

## Plan report to the system agent (2026-10-21, code.dispatcher.agent#10)

- When the last ticket of a plan, the tickets tied by `after_work`, is done, one project update of kind `plan_report` says so, once for the plan: its tickets by outcome, from its first ticket to the one just done. It is heard on the `done` kind the map now says beside `ticket` on a ticket's end (`plan_changed`, a `map.changed` subscription that reads nothing for any other change), and it wakes the system agent, since the person waits for the job's end.


## Official Antigravity ACP (2026-10-21, code.dispatcher.agent#fe)

- Google Antigravity replaces the retired Google CLI throughout dispatch, ticket agent choices, roundtable seats, pickers, setup and help. Removed the retired adapter, its setting declarations, hook branch, reminder setting and obsolete tests/docs.
- Default command `metaform dispatch adapter antigravity-acp@1.4.1` launches Google LLC’s native archive from the shipped official ACP Registry manifest. Installation reuses registry snapshots and archive handling. The launcher replaces itself with the native process. Native zip companions retain owner execution permission.
- Settings migrate transactionally per database, retaining custom commands and all unrelated fields. New explicit choices win collisions. Ticket agents and eligibility migrate through map upgrade 23. Required legacy identifiers survive only at migration boundaries and in their tests. Google’s documented active Antigravity paths remain intact.

## Ticket branches start from committed HEAD (2026-10-21)

- New worktrees exclude shared uncommitted files. Startup records committed HEAD as the merge base without creating a snapshot commit. Shared staging, edits, deletions and drafts stay intact. Older snapshot references remain valid for merges.

## Every message between agents is one line (2026-10-21)

- Every delivery from one agent to another reaches its receiver as one line, `Agent Name: Task Phrase: Message`, the `peer_note` prompt: the sender's agent and ticket number, its ticket's title cut to 80 characters, and its summary or the note's first sentence cut to 200 characters by the code, whatever the agent wrote. A note holding more ends with `(the whole: dispatch_notes note=<id>)`; the whole stays in the sender's thread on its ticket and in each receiver's. It applies to peer notes, the replies a question's wait returns or later gives as turns, the results, check-ins and change orders orchestration sends, and each entry of the system agent's inbox as `dispatch notes` lists it. `peering.line` replaces the runner's `inbox_phrase` and its 160-character `PHRASE`, and the inbox list's `inbox_line`; the person's relayed decision is still their own message, given whole.

## Session reads follow the view (2026-10-21)

- Session lists select running, waiting and recently ended rows before reading their state and signals. Older ended sessions require explicit cursor paging. Named session and ticket reads retain complete detail. The board batches its shown ticket IDs. Event handlers batch named session IDs and filter unrelated chat events.
- Tables version 19 adds the optional `ended` timestamp and indexes on session state/end time and session-line kind. Compatibility stays at 5 because columns and indexes are additive. Legacy rows without end times remain available through history and detail reads.
- Removed the ended-state process cache, all-session hydration before list filtering, ticket-wide event refreshes, and the browser's 500 ms agent-read delay.

## Agents have names (2026-10-21; names made deterministic 2026-10-25)

- Every session is named as it starts: two words from `resources/names`, an adjective then a noun, each capitalized and joined with nothing between, `StableComet`, worked out from the session id alone (`names.py`, `session_name`): 32-bit FNV-1a of the id's UTF-8 bytes, folded to 16 bits, the high byte an index into the 256 adjectives and the low byte into the 256 nouns. The same id always gives the same name, so a resume keeps it; two live sessions may share one, and nothing avoids a clash. The name is kept on the state line as `name` in the write that records the session, and kept by the agents key for ended sessions (`ENDED_STATE`). The agent is told it once, the `named` prompt, at the head of its first turn and again after a compaction. `sessions id=`, `talk session=` and `resume` (`id` or `session`) take a name for the latest session of that name; `named_session` resolves it. A task's `agent_name` no longer sets a name: the noun is gone from `tasks assign`. The first design, words ranked against the ticket's title and task through Jev with clash avoidance, the prompts `name_adjective`, `name_noun`, `name_true` and `name_false`, and the hyphenated lower-case form, is removed (ticket code.interface.graphical#1aa began it). No table change.

## Completed ticket records (2026-10-21)

- Shared-tree completions and worktree squashes retain ticket titles, resolutions, reasons and five identity trailers. Empty completions create empty commits. Cancelled and failed tickets create no completion commit. Dirty worktrees remain until abandoned-branch retention expires. Missing commits file numbered broken tickets on the original board.

## Only the active board runs by itself (2026-10-21)

- The gate refuses every start the system makes by itself for a ticket whose board is not the map's active board (`board` setting), Full Auto on or off, saying the board is set aside; the person's own start still runs. The agent starter considers only the active board's tickets. `ticket_settings` reads each ticket's board.

## The session drift check is gone (2026-10-20)

- Removed the Jev `session_drift` decision and the runner's drift check with it: every ten tool calls it sent Jev the task and the last twenty calls with one yes/no question per call, per conclusion read and per step window. A classifier cannot judge from a call's title and 400 characters of its input whether the work needed it; the answers it gave were near coin flips and raised nothing, and the asking spent the OpenRouter credit. The `drift` signal is no longer raised; the spin count, `dispatch_spin_calls`, stands as the signal that an agent may be looping.

## GC-led swarm orchestration

- Bound authored GC, specialist and independent functionality responsibilities through public role resolution while retaining the existing operational execution role and configured controls.
- Added durable parent/team/caller relationships, child suspension and resume through the existing admission gate, GC-owned generated roles, independent assessment and corrective continuations, retained direction, and actual Chat notifications.
- Removed fixed peer-note length, hourly, pair and reach caps. Ordinary agent messages are authenticated peer notes; only a recorded GC broadcasts to or interrupts its own swarm. Registered editor sessions also receive ordinary peer turns.
- Actual ACP delivery now records rendered prompt versions and context epochs, suppresses unchanged components, and receives relevant functional memory changes. Source-backed selected prompt updates preserve component identity and user override history.
- Added focused and subprocess fixtures for configured-capacity-one nested returns, generated role reuse, GC/FQC change orders, strict recommendations, peer delivery, restart, prompt receipts, memory correction and event costs.

Each change to the dispatch module, newest first.
