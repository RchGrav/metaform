Each change to the dispatch module, newest first.

## Unreleased

- A linked file stays where it is linked, code.graph.knowledge#17 (Rich, 2026-10-15): refs are not properties, so `link` no longer moves a file's ref to the nearest common node of two places. A file already linked elsewhere gets a second ref at the element named, with a name of its own. No table changed.
- The memory prompt in a worker's first turn, code.store.memory#3 (Rich, 2026-10-15, CTX-026 to CTX-029): the first turn starts with the owner's memory prompt, filled with the project and the ticket's element (a join's receiver), taken from the memory module's `memory.prompt` while memory is on the folder's surface. `record`, `on_ticket_done`, `on_stopped_open`, `on_failure` and `work_record` no longer carry the 2026-10-11 sentence on storing what is learned; each asks for memory and knowledge as the memory prompt splits them, a draft awaiting the owner's approval. No table changed.
- A linked file is a ref record, code.graph.knowledge#c (Rich, 2026-10-15): `link` writes the file's ref as a record of its own in the `sources` layer through the store's `link_ref`, named by the new `ref=` noun or from the path, with who linked it (the runner's work and session, or the surface) and the new `why=`; it answers the ref's name `{ref_id}@{address}` and id. A file linked at another place moves to the nearest common node of the two. A name taken or reserved writes nothing and is answered, exit 0. The runner's `sources_index` reads the store's ref records. No table changed; the base store's layout is 22.
- The hand-off carries the person's note, code.graph.knowledge#d (Rich, 2026-10-15): when the person has written a note at the ticket's node, the hand-off's fields include it whole as `the person's note here:`, read through the memory module's `memory.note`, until pushed delivery is built. No table changed.

- No nonces, BASE-050: an agent dispatch starts over ACP is given its work by the session itself, the hand-off as its first prompt and `METAFORM_ROLE`, `METAFORM_SESSION`, `METAFORM_WORK` and `METAFORM_NODE` for its MCP server, so the runner requests no nonce. `handoff id=<work id>` prints the ticket's hand-off prompt and its nodes for the agent the work is handed to by id; the `handed` prompt is gone. The intake's text waits in its launch's `raised` row, the new `asked` column, which the runner reads and clears before its session is made; `run` no longer takes `asked`. Recovery evidence is the session row's private `recovery` column. Tables version 9 adds both columns, which may be empty, so version 5's code still reads and writes the tables; `nonce` stays in `sessions` for rows written before and is no longer written.
- Record on finish, BASE-052: the new setting `dispatch_record_on_finish` (off, when-missing, always; `when-missing` by default) gives a worker whose ticket is done one more turn, the `on_ticket_done` prompt, before its session ends, when its session wrote no memory join or observation at the ticket's node, told by `by` against the session's `runner`. `on_ticket_done` ships empty until its wording is written, and empty sends nothing. The memory module is read through its `joins` and `graph` verbs, `memory_read`, without importing it. The fake agent's `done` mode records a memory first with `FAKE_ACP_RECORD`.
- The queue moves without the page, VIEW-042 and BASE-052: a runner that has finished its sessions runs `autostart` in its own process, which recovers dead runners first and starts nothing when Autostart agents is unchecked. `autostart` counts free slots and reserves the tickets that fill them in one write transaction on the work store, so the page's check and a runner's never fill one slot twice; the runners start after it commits, through `run_reserved`, which `start` uses too.
- Steering goes by role, BASE-052 and MAP-050: `start`, `stop`, `message`, `interrupt`, `resume`, `configure` and `permit` refuse an agent whose role the person's `roles_without_authority` names, `worker` and `prep` by default, on the CLI and over MCP; the page is never refused. A message an agent sends is a `message` line, `From the <role> agent: …`, and no longer a `person` line.
- `wait until=done|stopped|signal [id=] [since=]`, BASE-052: an orchestrator blocks until a ticket is done, its agent stopped with it open, or a signal is raised on it, for at most the new setting `dispatch_wait_seconds`, 50 by default, and gets `pending` with the next call at the limit. With no id it waits on every ticket of the project and names which woke it. It wakes on `map.changed` through `ctx.listen`, never on a timer, QUAL-015.
- ACP used to its fullest for the page, BASE-052 and VIEW-039: the agent's capabilities, settings (its modes and config options, a model among them), slash commands, plan, usage and the parts of the map it touched are the session's `state` line; each tool call's diffs, locations and terminals are a `tool_detail` line, each file placed on the map through the `sources` layer's refs; each permission request is a `permission` line with its options. `sessions` returns the states under `states` and each structured line's JSON as `data`. New verbs: `agents` lists the agents with whether each start command is found and the default; `intake` starts an agent on the project's intake, VIEW-045; `resume` resumes an ended session in place through `session/resume` or `session/load`; `permit` and `configure`, CLI only, answer a permission request and set a session's mode or model. `start` no longer makes the agent it started the default, and `system` uses the default agent. The fake agent offers modes, a model option, commands, an edit and `session/load` when asked.
- One agent per glyph, VIEW-040: a runner started on a ticket with an agent glyph works the glyph's tickets one after another in board order, a session for each, the next taken when the one before is done; `start` and `run` refuse a ticket whose glyph's agent is at work and name the ticket it works. The glyph is read through the base's `work_reads`. The fake agent names each process's session by the sessions made before it, and its `done` mode closes the ticket its prompt names.
- The runner hears `map.changed` from other processes through the base's listener, `ctx.listen`, BASE-053. dispatch's `map.changed` subscriber, `relayed`, `RUNNER` and the control port's `changed` request are gone; the port takes `message` and `stop`.
- A question a dispatched agent asks itself with `map ask` is told to it when the person answers it, as the `answered` prompt, BASE-052. The runner knows the question by its id in the output of one of the agent's own tool calls, made no earlier than that call began.
- A ticket's sessions show on its work record, BASE-035: dispatch's `work_read` adds `{"sessions": [...]}` under `dispatch` in `metaform map work id=<id>`, each session from dispatch's own table without what only reaches a running session.
- dispatch reads its prompts with `metaform.prompt_files`, now part of the public base, BASE-004 and MCP-031, and no longer carries its own copy of the reader.
- dispatch is made from the template at its changelog's Unreleased contract, BASE-019 and BASE-052: `start`, `run`, `message`, `stop` and `handoff`, the `dispatch_claude`, `dispatch_codex` and `dispatch_gemini` settings, the `dispatch` layer, and a `map.changed` subscriber.
