- **AUE** (Artifact Under Examination): A software tool, plugin, utility, or independant part, include its file assets which can be reasoned as a separate thing can be an AUE in the same parger project, but must be mapped into the whole properly, when there is multiple documents, photos, or individual files these must be analyzed individually, multiple items and its assets is an AUETreat each photograph, document
- **Join**: A dictionary object that exists in the Receiving Element (RE); it contains a dictionary of objects containing type specific or AUE specific references and logic.
- **Element**: An element is anything nameable as a type; however, just because an element can be named doesn't mean it is interesting, remarkable, or deserving of special attention. Many elements can be immediately seen, or are easily inferred.
- **OP** (Operative Purpose): The **why**. This is the active goal held in an RE's dependency dictionary — that an element's encounter function intends to accomplish as a sentence fragment.
- **EF** (Encounter Function): The **how** of what is delivered. This is the mechanism, interface, relationship, or method through which an AUE or Element performs its purpose for its RE. It explains how the effect is encountered, used, or experienced written as a sentence fragment.
- **RE** (Receiving Element): The **who** or **what** bearing an OP. This is the element, person, group, system, component, or other participant with an Operative Purpose for the Encounter Function of an Element. The OP belongs to that receiver, and the dependency that records it lives in that receiver.
- **CQU** (Cestui Que Use): The explicit RE which benefits from work which can be performed on the type of thing the artifact is: the type or party that holds an objective purpose for this type of object and drives the most improvement in it. The CQU is a party type outside the AUE, typically a human or an organization; it is never an element of the AUE. The CQU receives the join, holding the Operative Purpose that a Providing Element's Encounter Function serves.
- **PE** (Providing Element): The part satisfying the requirement actively declared by its RE through its Operative Purpose. This is the join's other endpoint: whatever's EF fulfills the RE's OP.
- **AT** (Artifact Type): This is a general category or classification that groups individual artifacts together based on shared characteristics. Artifact Types can be used to anneal or combine many of the same type of AUE into types (for example photos, data objects, scripts, templates, etc).
- **NE** (Notable Element): A component, interface, or specification that defines an essential demand or requirement. It is **notable** because it highlights what a system or component explicitly expects, needs, or depends on from its external environment to operate successfully.
- **DE** (Defining Element): The notable element of this AUE whose loss would prevent the AUE from remaining the same type. Its Encounter Function services the OP of a CQU outside of this AUE, names the functional type of the AUE as a converged result of the functionality of the AUE being examined. Its defining function is expressed independently of medium, encoding, genre, and style.
- **SE** (Supportive Element): An element whose Encounter Function helps the DE serve the CQU's OP. It counts as substantial because of what it is meant to contribute to this AUE, even when that contribution is subversive, weak, replaceable, or should be improved.
- **UD** (Upstream Dependency): An element outside the AUE that an RE depends on.
- **DD** (Downstream Dependant): An element outside the AUE that depends on an element as a PE and is not a person. A person who depends on the AUE is a CQU; a thing that depends on it, such as a project built on this one, is a DD.
- **Parametric**: A quality or quantity that can be tuned but does not carry a specific name in the scope of the namespace of this AUE. We do not name parametrics with a namespace address in this graph or as part of this operation.
- **NS** (Namespace Scope): The scope of the Artifact Type. The five base valid types are code, document, media, data, upstream and downstream.
- **IFD** (Information Flow Direction): A direction [send|receive|both] assigned to a movement of substance as a requirement that satisfies the OP of the RE.
