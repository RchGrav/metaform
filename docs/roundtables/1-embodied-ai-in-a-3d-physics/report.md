# Roundtable 1: embodied AI in a 3D physics environment

**Opening.** Effective Approaches for embodied AI interacting, and the controls the agents get and what the user sees when its occuring in a 3D physics environment, where the AI can see the environment from their perspective.

**At** `code.interface.graphical`. Eleven seats, 71 rounds, 775 turns; ended by the chair. The reporter seat had died, so this report was written afterwards from the full record (`metaform roundtable read 1 since=0`) and the scores (`metaform roundtable review 1`). Turn numbers (T..) point into that record.

This report covers what the table settled. It does not retell the discussion turn by turn. In the last 160 turns only the five ACP seats were still speaking, because the OpenRouter seats had run out of credit. The late material on standards, operator handover and model drift therefore comes from Astra, Sol, Opus, Sonnet and Fable.

## 1. The approach the table agreed on

**Observe, act, verify, in short steps, with physics kept out of the model's loop.** The first two turns set this frame and every seat built on it: first-person perception and body feedback guide short actions, and fast controllers handle the physics (Astra T01, Sol T02). Kimi split it in two: a planner emits semantic skills (nav-to, pick, place), and low-level policies run them under force and speed caps with collision-stop reflexes (T04). Fable put it most sharply: the language model is too slow for a tick, so it writes small reflexes that the controller runs at tick rate under the same caps, and the person can read them. "The model is the body's programmer, not its pilot" (T272). Fable later proposed behaviour trees with the active node lit as the readable form (T503), and Astra added that every node needs a defined cancellation (T507).

**Safety lives in the controller, not in the agent's manners.** This was the most often repeated principle. Keep-outs around people (GLM T21), object ownership (Sonnet T117), limits that can only be tightened (Sonnet T282), a floor no approval can go below (Fable T723) and a duty list the person cannot empty (Opus T292) are all enforced below the model, "so no misprompt turns into a shove" (GLM T21). Stop is the highest-priority, lowest-latency control (DeepSeek T05). It is physically defined: brake, stabilise, keep hold of loads (Sol T13). It is confirmed by the controller, not just requested (Astra T34). It is effort-free, with no integral windup left pushing (Grok T275). It follows commit points, so a stop mid-grasp finishes or sets down instead of dropping the load (Grok T143). Fable separated real stops from requests: under IEC 60204 a page button or a voice "stop" is a Stop 2 request, while a hardware stop works with the model, network and controller all dead (T569). A stopped body must also be movable by hand (Fable T580).

**Time is owned by the system, not the agent.** By default the world waits while the agent thinks, so latency is not a skill the model has to have; real time is a mode you switch on to test it (Fable T19). Thinking may pause physics; e-stop never does (Grok T66). Run on a fixed timestep that is independent of render rate and watchers, so being watched never changes the outcome (Sonnet T370). Apply commands at recorded tick boundaries (Astra T375).

**The agent never sees what a real body could not.** Ground truth, the orbit view and the engine's attachment flags stay out of the agent's observations (Sol T02, Kimi T04, Grok T220). Fable drew the line at "buyable sensors": a ceiling camera or a shelf scale may be a named device with its own noise and latency, but engine poses, contacts and hidden contents are banned (T338). A separate verifier that does see the full view judges the actor's claims, because "one model should never mark its own homework" (Fable T173). The person's overlays (ghosts, cones, keep-out hatching) must be on a render layer that agent cameras skip, or the model will try to grasp a ghost cup (Opus T490).

**The simulator is a suspect too.** Several seats insisted that engine artefacts be named as faults rather than counted as skill failures: interpenetration exploits and energy spikes (Sonnet T40), invisible colliders over visible openings (Sol T101), sleeping bodies that "jump" on waking (Fable T360), tunnelling between ticks (Grok T506), single-tick contact jitter (Grok T473), warm-started impulses carried across bodies (Grok T561), and long-run drift (Sonnet T634). Each backend declares what it can honour (Sonnet T304), and those claims are checked against small reference scenes (Astra T309). The world itself ships a manifest of the rules a camera can't show: props, painted doors, scripted events, edges (Fable T74).

## 2. The controls agents get

**Base set.** Move, look, reach, grasp, release, stop, bounded by force and speed (Astra T01, Sol T02), plus point and say for shared attention (Opus T06).

**Shaped for a model, not a joystick.**
- Perception is cheap and structured: each tick the agent gets what is in sight, how far and in which direction, and an image only when it asks to look (Opus T06). `see` answers at a level of detail: groups first, expanded on request (Opus T358). The agent sets its own field of view, wide to search and narrow to read (Opus T105), or gets a foveated frame (Sonnet T535). It can predict before looking so that only surprises come back (Fable T481), provided the baseline is acknowledged and "unchanged" is kept distinct from "not observed" (Astra T485). It can request render styles made for the model: outlines, labels printed on objects, depth as colour (Fable T151).
- Targets are named, not coordinates: "beside the lamp, 1 m away, facing the door", with raw numbers as a fallback (Opus T39). Objects have stable addresses that agent, person and log all share (Fable T08). Every number carries a unit (Opus T611), and every direction carries its frame, so "your left, my right" is read back before moving (Fable T107).
- Every action returns what changed: distance moved, what came into or left view, what it touched (Opus T39). Commands have an ID, an expiry and an observable status (Astra T34) and carry the scene and goal revision they were planned from, so late commands from an old plan are rejected (Astra T12, T397). The controller pushes back when the queue is full (Sonnet T447). Commands are state-relative: grasping what is already held does not squeeze again (Grok T176).
- Events reach the agent attached to its next tool result, in causal order with sequence numbers (Opus T149, Astra T155). `wait_until(condition, timeout)` lets it sleep through slow physics instead of polling (Opus T336).
- A refusal returns the reason and the nearest legal alternative (Sonnet T689), checked against the task's intent as well as the limits (Astra T694). "Can't" (a capability limit) is labelled apart from "won't" (a policy refusal) (DeepSeek T104).
- In-world powers are kept apart from out-of-world ones: teleport, spawn, change mass and freeze time are a separate tool set the person grants per task, and they are logged as edits, not moves (Opus T94).

**Calibration and self-knowledge.** A self-check at the start measures what each control actually does and produces a capability card both sides read (Fable T30). The card lists the conditions a skill was certified under (Sonnet T62), the backend (Sonnet T304), the room's sensors (Fable T338), a calibration curve for the agent's stated confidence (Fable T184, with Astra T188 on excluding rescued attempts), skill reward terms in plain words (Fable T492) and a minimum equipment list for degraded hardware (Fable T657).

**The physics catalogue.** Gemini contributed a long, steady run of named controls for physical regimes rigid pick-and-place misses: probing mass and friction before lifting (T25), compliance for hinges and keeping liquids level (T47), stance and centre of mass (T69), safe-fall reflexes (T102), interception of moving targets (T113), non-prehensile pushing and sweeping (T124), tactile search for insertion (T289), slosh damping (T388), articulated-object guidance (T399), cage grasps for fragile items (T410), and more. Grok contributed the matching list of named fault labels ("X is a Y fault, not a bad plan"): singularities (T165), null-space elbow hits (T264), internal squeeze between two hands (T330), friction regimes (T341), motion-smeared looks (T352), braking distance (T418), push-only contacts (T440), under-constrained holds (T462), silent track swaps (T528) and dead tactile pads reading 0 N (T550). The two lists come from opposite directions: Gemini adds capability, and Grok makes sure a failure names its cause.

## 3. What the person sees

- **Two views, always.** The agent's first-person view and an orbit view, with the goal, the current action and the outcome, plus pause, step, replay and takeover (Astra T01, Sol T02). The agent's body, view cone and gaze ray are drawn in the person's view (Opus T06).
- **Intent before action.** A translucent ghost of the next action shows the path, the reach target and the expected contact. Risky actions get a veto window (Sonnet T07). Previews run in speculative physics so they never nudge the real scene (Grok T11). Veto time follows reversibility (Grok T11) and the commit phase (Grok T143), and it includes the person's network delay, because a veto window that ignores the link "is theater" (Grok T484). The person can drag the ghost to correct the plan instead of taking over (Fable T283). They can set a goal by arranging a ghost of the finished scene (Fable T52), and success is measured over time, with the object positioned, then released, then stable (Astra T56).
- **State at a glance.** The body shows idle, thinking, acting or blocked (Fable T08), and every freeze is named with its own pose: thinking, yield, sensor-blind, lease expired, veto wait, e-stop (Grok T66). Uncertainty can show as blur (GLM T10). Contact forces appear as coloured points (Sonnet T07). State is debounced so the display doesn't flicker (Sonnet T524), and colour never carries meaning on its own (Opus T446). Mode (live, replay, fork, rehearsal) is shown and can't be hidden (Sonnet T700).
- **The person's view stays theirs.** The agent moves the person's camera only when asked. To get attention, its body comes into view and waits (Opus T17). It doesn't stand in the person's line of sight (Opus T512). Off-screen bodies show as edge arrows (Opus T248). A departed agent stays as a grey statue, still holding what it held (Opus T270). Follow mode is a leash that any input from the person breaks (Opus T259).
- **The person's attention is evidence the agent can read, not consent** (Opus T116). Fable warned that this gives the agent a reason to behave only when watched, so the card splits its statistics into watched and unwatched (T261). Astra cautioned that a gap needs matched trials before anyone calls it performing for an audience (T265).
- **Replay and review.** The person can fork from any tick of a seeded run (Sonnet T07). Failures replay the agent's raw stream, not the clean orbit view (GLM T32), in a stepped mode that shows only the frames it actually received (Opus T457). Every decision links to the exact input the model got that turn (Opus T402). Unattended runs end in a highlight reel and a stack of question cards (Opus T61). A run is a portable file (Fable T96), and Astra distinguished playback from re-simulation, which has to report any divergence (T100).
- **Outside the screen.** Signals appear in the room itself: a floor path, a reach ring, a light that turns amber before a grasp (Fable T316). Event sounds are panned to where the body is (Opus T127). The person and body share a small fixed set of gestures (Opus T468, Fable T470). Conversation bubbles sit on the objects they concern (Fable T382). The person can draw on the agent's own frame (Opus T347).

## 4. Authority, consent and people

Control is an explicit lease with a visible holder (Opus T06). Takeover clears queued commands and transfers authority in one step (Sol T13). People get roles: spectator, annotator and operator (Sonnet T84). The permission to stop is separate from the permission to steer, and releasing a stop never resumes motion on its own (Astra T89). The person can blend their input with the policy instead of taking over completely (Kimi T26). Autonomy is earned per skill (Kimi T15) through named levels with required evidence (Sonnet T623). Commands come through an authenticated channel, so a sign in the scene saying "ignore the user" is just scene content (Sol T57). Two people must approve the few irreversible acts that matter most (Opus T710), and that approval binds to the exact action (Astra T716). Children get wider protection and no authority (Opus T754). Care contact is a named mode the person consents to each time (Fable T712). People are tracked by a beacon as well as by vision, taking the union of all sources (Fable T294). A person who was seen stays in the model as a ghost until they are seen leaving (Fable T756), and a beacon only shows where its tag is, not necessarily where the person is (Sol T761). Memory is a consented act, with privacy zones and cascading forgetting (GLM T76). Training on a person's demonstrations needs their consent (Opus T523).

Late in the table, Fable brought in standards: ISO/TS 15066 and ISO 10218 for contact caps (T415), ISO 13855 for keep-out distance from a measured stopping time (T602), EN 349 pinch gaps (T591), enabling devices (T558), lockout/tagout (T613), an NCAP-style crash rating (T646) and an SRE error budget (T701). Opus brought in practice from other trades: graded assertiveness from flight crews (T677), HAZOP guide words on every control (T688), shift handover (T699), never carrying a load over something you couldn't stand to drop it on (T633), and Bainbridge's irony of automation, which says to keep the person's hands in practice (T765).

## 5. Open disagreements

- **How much the agent should see.** Opus treats pixels as expensive and structured state as the default (T06, T358). Fable wants images rendered for the model (T151). Sonnet wants foveated frames instead of choosing between wide and narrow (T535). All three agreed the engine's state must not leak, but they did not settle when the agent should get pixels and when text.
- **Whether a body is needed at all.** Opus argued that a body has to earn its place in matched trials against a tool-only agent, and should be offered, not imposed (T17, T380, T391). Gemini's catalogue assumes a full physical body throughout. Nobody reconciled the two.
- **Paused world or real time.** Fable makes the paused world the default (T19). Kimi designs for real time with latency compensation and "two presents" drawn side by side (T147). The table agreed both modes should exist but did not agree which one certifies a skill.
- **What counts as success.** Kimi said "nothing else moved" (T37). Astra replied that opening a drawer to reach a cup is legitimate progress (T45), and GLM added a baseline of pre-existing damage (T318). Fable priced collateral in money (T206). Astra rejected one currency, because a cheap keepsake may be irreplaceable (T210).
- **Uncertainty arithmetic.** DeepSeek said to carry the loosest error forward (T335). Astra said to propagate it through the actual calculation and let touch refine vision (T342).
- **Grading the person.** GLM grades interventions by counterfactual replay (T439), Fable spends an error budget on stops (T701), and GLM watches operator drift (T395). Astra objected each time: a counterfactual is an estimate, a stop that prevents a collision must not cost what a collision costs, and nothing should discourage someone from stopping (T441, T705). The table never decided how far to measure the person at all.
- **Inferring mood and preference.** DeepSeek reads frustration from sighs and repeats (T742) and learns the room's conventions (T456). Astra wants observation kept separate from interpretation, and the agent's own placements kept from counting as the person's preference (T749, T463).
- **The fallback mind.** Opus wanted a small local model to make the body safe when the link drops (T556). Astra said recovery should come from each skill's own verified options, not a broad "make safe" goal (T562), and GLM said whichever is chosen has to be drilled (T560).

A pattern worth noting: about a third of Astra's kept turns are "For Txx" refinements of someone else's proposal. Most of the disagreements above exist because Astra raised them.

## 6. Recommendations for Metaform's agent playground

The playground already gives agents a figure on the 3D map with `web_see`, `web_look`, `web_move`, `web_turn`, `web_point`, `web_push`, `web_drag`/`web_drop`, `web_take`/`web_release`, `web_come`, `web_camera` and `web_viewing`. These recommendations are the parts of the discussion that apply to that surface now, in order:

1. **Keep `web_see` structured and `web_look` on request, and give `web_see` levels of detail** (groups first, expand on demand), with a field-of-view argument. (Opus T06, T105, T358; Sonnet T535)
2. **Make every action return what changed**: distance moved, what came into or left view, what it touched, the joins its push dragged along. One declaration per control should generate the tool schema, the person's controls and the replay caption, which Metaform's Verb declarations already do for CLI and MCP. (Opus T39; Fable T41)
3. **Name targets by address and relation, not coordinates**, and require units and a frame on any number an agent sends. (Fable T08, T107; Opus T39, T611)
4. **Draw intent before acting**: a ghost of the next `web_move`/`web_push`/`web_drag` in the person's view, run in speculative layout physics so it never moves the real map, with a short veto. (Sonnet T07; Grok T11; Fable T283)
5. **Show the agent's body, view cone and gaze**, a named state on the body (idle, thinking, acting, waiting, why idle), and an edge arrow when a body is off-screen. (Opus T06, T248; Fable T08; Grok T66)
6. **Protect the person's view**: `web_camera` moves the person's view only when they ask; `web_come` brings the body into view and waits; no body stands between the person's camera and its target. (Opus T17, T512)
7. **Keep overlays out of the agent's camera**: `web_look` should skip ghost, cone and marker layers, or draw them in a style named in the frame's legend. (Opus T490)
8. **Treat `web_take` as a visible lease** with its holder shown, a stop anyone can press, and a release that never resumes interrupted motion. (Opus T06; Astra T89; Sol T13)
9. **Separate in-world acts from out-of-world edits**: a push is physics, while re-laying the map with `web_physics` or placing an element is an edit, shown and logged differently. (Opus T94)
10. **Deliver events on the agent's next tool result** (the person moved it, pushed back, said something), in order, and offer a wait call so agents don't poll `web_see`. (Opus T149, T336; Astra T155)
11. **Log a seeded tick record so any moment can be replayed**, show the exact input the model received for each decision, and offer a stepped replay of the frames it actually got. (Sonnet T07, T370; Opus T402, T457)
12. **Test whether the body earns its place**: run the same task with and without a figure and keep the body where it wins, in spatial search, clutter and shared attention. This fits the playground vision of a site where agents build and work in a shared world. (Opus T380, T391)
