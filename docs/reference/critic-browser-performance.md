# Browser performance investigation

Use this reference when the assigned target is browser or graphics performance. Record the behavior and fidelity the requested change must preserve.

- **Performance means cheaper frames, never fewer.** A performance finding names what each frame actually does that costs time: per-element work that could be batched, whole-scene redraws, per-frame allocations, layout reads, draw calls. Its fix makes that work cheaper or removes it, at the display's full refresh rate. An idle frame-rate cap or a lower frame rate is a regression, even when it lowers CPU at rest. Stopping the loop when nothing on screen moves at all is fine. Measure headless only: on this machine WSLg puts every headed window on Rich's screen, even one placed off-screen, so never launch a headed browser. Headless reaches the real GPU with Playwright `chromium.launch(channel='chromium', headless=True, args=['--headless=new','--enable-gpu','--ignore-gpu-blocklist','--use-gl=angle','--use-angle=gl-egl'])`; record the renderer string with every number. Run every browser script as `env -u DISPLAY -u WAYLAND_DISPLAY <command>`, so no window can appear even by mistake; the GPU works without them. Report frame time p50/p95, draw calls per frame and per-frame JS by function, against the last commit.
