# Changing Metaform

Read the one subfile for the class of work you are in before editing. Each rule came from a real defect in this repo.

## Tickets and source passes
Report each step with its own `metaform map work op=step` (one note over steps 3 to 6 left the board at 5 of 8; on 2026-10-14 the notes "Steps 5-6" and "Steps 7-9" left it at 4 of 9, so count per step, never a range), and close with `op=done` only after the acceptance checks pass. `op=plan` takes only a step count and drops its `said` text, so write the numbered plan into the first `op=step` or into `op=edit note=`, then read the ticket back to confirm it landed. Never edit a spec record from a ticket; the person writes specs, and a record's `Built` line is part of the record. Put the built state in the step text and the `op=done` resolution, and name the record line in the report for the person to amend. Where code and a spec record disagree, the code is the reference: never change code to match the record, since that rolls back features; report the difference and draft the record text in `artifacts/specs-draft/`. A worker agent cannot `op=add` a ticket (refused: tickets are written by the person and the agents that serve them), so a follow-up ticket goes into its own ticket's `op=edit` note for the orchestrator to file. Spec text drafted for the person goes to `artifacts/specs-draft/`, never `specifications/`, until the person approves that exact wording. Once they approve it (for example "the spec is APPROVED; build it now"), the approved wording goes into the spec file as an amendment bullet marked with the date and `approved by the owner`, the view record that cites the rule gets a matching amendment and its Relates-to line updated, and the report names both bullets so the person can review or reverse them. When a design is replaced, delete the memory observations that describe the old one. When a notice says a ticket's task has been replaced, re-read the ticket with `map_work` before more work, and do not restore the replaced behaviour. A ticket assigned to one module does not edit `src/metaform/*.py`. In a shared tree where another agent already has uncommitted edits in a file, change only your own lines and do not commit without the person's yes. When the `metaform` MCP server fails to connect (on 2026-10-14 with `No module named 'yaml'`), its tools are gone for the session. Say so in the report and in the ticket's `op=edit` note, then do the ticket and memory writes through the CLI (`uv run metaform map work op=step id=ID said="..."`, `uv run metaform memory ...`), and do not present the CLI route as a fix. Memory argument shapes through the CLI: `create_entities` takes a JSON list of `{name, entityType, observations}` with `node=NODE`; to correct a stale observation, read it back with `open_nodes`, then `delete_observations` takes `[{entityName, observations:[exact old text]}]` and `add_observations` takes `[{entityName, contents:[new text]}]`, both with `node=NODE`. Memory citations (`memory_create_entities` `cite`) resolve only inside the project folder the MCP server runs in: a path in a sibling repo such as /home/rich/roundtable fails the whole entry, so cite project files or leave `cite` out and name the other repo in the text. Full rules, including source passes and source_placement runs: `references/ticket-work.md`.

## Public base additions
A module reaches chassis code only through the public base (`metaform.module`, `settings`, `data`, `events`, `prompt_files`, `axiom`, `home`, `outline`, `finish_xml`). A helper a module needs from elsewhere in the chassis (`src/metaform/sqlite.py`, say) is re-exported from a public module, never imported directly: `tests/test_base.py::test_every_shipped_module_imports_only_the_public_base` fails on any other import, and so does another agent's `metaform.skills` import. Each addition is written into `modules/template` (code, README, `CHANGELOG.md` Unreleased) in the same change.

## Module verbs and settings
A verb or setting lands as one unit: the module's `__init__.py` declaration, its `README.md`, its `CHANGELOG.md` Unreleased entry, and the spec bullet it cites, with tests in the module's existing test file. A module with no `CHANGELOG.md` gets no entry; its README still changes. When only a verb's `effect` or `open_world` changes, its row in `docs/reference/metaform-mcp-server.md` changes too: that file's tables are generated from the running server, so the Effect column (`write, open world`, `read`, `remove`) must match the declaration. A verb's `caution` text changes its row the same way (the server shows it as `summary Caution: text`). A caution is enforced on both surfaces: MCP stops the call without `confirm: true`, and the CLI stops it without `--confirm` (`cli.py`, `if verb.caution and not parsed.confirm`). So when a verb gains a caution, grep `tests/` and `src/` for its CLI form and add `--confirm` to each call that must still run, and add a test that asks for the confirm over MCP. Next-step texts that print the bare command (`metaform map activate <name>`) now lead to a stop; say so in the report rather than editing them silently. A fixed set is a choice setting, never free text. Tests: a project-place test module needs `SUPPORTED_OS`, or it loads with `SUPPORTED_OS is required` and its setting 404s. When a ticket session has `METAFORM_ROLE`, `METAFORM_SESSION`, `METAFORM_WORK` or `METAFORM_NODE` set, unset them for the pytest run. Browser tests (`-m browser`) passed under `METAFORM_BUILD_VIEWS=1`. A running web server keeps its old code until restarted. A setting's choices function (`setting.options(folder)`) runs on every `tools/list`, `config --show`, help and select validation, so it does no network or other slow I/O: a remote list is kept in a module table that its own verb writes (that verb's effect becomes `write`, which the MCP declaration guard checks), with a published constant as fallback. Module tables have only the `metaform` and `project` places (`data/tables.py` Place), so such a list is per project; a home-wide place is a chassis change, outside a module ticket. Update the module README's verb row with the declaration. A setting holds a whole number only (`settings.number`), so a dollar or other fractional limit is a whole-number setting, and the fraction is taken as the verb's argument (`spend=0.50`). A setting the person marks `person_only` binds agents too: MCP `set_schema` omits it and `refuse_person_only` refuses it, and a limit among them: a verb that takes an agent-supplied override may only tighten the setting, and refuses a looser value saying only the person can raise it. Independent choices get one setting each: a single list setting holding many entries loses the others whenever one is saved. A list is stored member by member, never as comma text, on every web path: the settings screen draws a list without choices as a textarea, one item per line (`itemsBox` in `page/app/settings/screen.js`), and saves the array of its trimmed non-empty lines; `/api/settings` refuses a string for a list kind with 400 `<switch> is a list: send its items as an array.`, so the server never splits at commas. The CLI still splits on commas, so an item holding a comma awaits the person's form. `set_setting` sends every list array to `save_list`; nothing joins a list with commas on the web path any more. A list the running server does not declare is saved by `stored_list_there`, which runs `store_list_here` in the project's own folder so that folder's modules load there. Never load another project's modules into the server's own process: the loader keeps one process-wide cache and takes its project from the server's cwd. The child's `-c` program names the module path in full, because the server runs as `__main__`. A switch whose stored value would silently change later calls of another kind (a transport, a dry run, `--raw`, `--critic`) is `per_call=True`: given on its call, never read from storage (`settings.value` ignores a stored row), refused by `set` with the verb that takes it named, and left out of the settings screens and `config --show`. A choice that lets agents act without asking is `risky` (a tuple, or a function of a Context): `set` needs `--confirm`, the set tool `confirm: true`, the screen and the page a yes, and stepping never lands on one. A reset, unglue or clear writes only at the folder's own scope (`own_scope_of`, never `scope_of`); a value inherited from a folder above is refused, naming that folder. Changing what a stored setting means needs a one-time migration, run from the module's start hook through the public `home.save`/`home.clear` calls so caches and change notices stay right. Wire the start hook last, and first run it against a scratch `METAFORM_HOME` seeded with the old names: the moment the hook lands, every live Metaform process on a shared tree runs it on the real home (a second process racing the first left a folder move unrecorded in the marker). A scratch home is a copy, so it carries the real project paths and project ids: a copy that runs a start hook moves the real project folders (on 2026-10-14 another session's copy of `~/.metaform` moved the person's five placement runs, 448M, into `/tmp` within a minute of the hook landing). Before the hook lands, search `/tmp` for homes that register `/home/rich` paths, and never let a scratch home point at a real project folder. Give each migration step its own marker: a marker an earlier step already wrote makes the new step never run. Make each step idempotent. A test home's own first start writes the migration marker, so a migration test removes that marker just before it calls the migration. Processes started before the change (the MCP server, live agent runners) still read the old declaration until restarted; say so in the report. Tab completion for a setting's choices works through `complete -C metaform metaform`, and module discovery must run inside that path too. Full rules: `references/module-changes.md`. Renaming a module is one change across its id, folder, tools, layers and settings: `git mv` the folder; rename the declaration id and tool names; rename the module's layer in every base (a layer-rename operation in the data layer, since none existed before); rewrite its members in the `modules`, `layers` and `jev_decisions` settings and in aliases; move the run folders out of each project folder's `.metaform/<old id>` into `projects/<project-id>/<new id>/` in the Metaform home, never leaving a `.metaform` tree in a project folder (intake and placement write run state only in the home, `getting-started.md` says so, and the run path must match `runs_root` and `pipeline._directory`); update prompts, README and help. Then re-record the memories under the new names and delete the ones that cite old paths. Recorded ticket text stays as written; the report names the running processes that still hold the old module.

## Changes that act on records already on the board
A change that lets autostart, a scheduler or any loop act on records already there runs them the moment it lands. Before it lands, count the live candidates from the person's real home, read-only, and say in the report how many will start, what each costs, and that the person may hold them first. On 2026-10-14 the marker change made eleven open markers that already existed into candidates for paid agents, one per node; the report named it only after the code was built. Verify such a change in a scratch home that is not a real project folder.

## Removing a module or feature
Delete it; never switch it off (the person's rule). Before deleting, find everything only it used: grep its names, tool names, routes, setting keys, prompt ids, vendored files, `docs/reference` rows, test entries and `artifacts/specs-draft` drafts across `src`, `tests`, `docs`, `specifications`, `artifacts` and the template module. After deleting, run `uv run ruff check src tests conftest.py` (an import the deleted code alone used shows as F401 in a file that stays) and `uv run metaform help`. A deleted page part hands its place in the load-order chain (the `workspace.js` imports) to the part before it, or every later part loads out of order. Run `git ls-files` on any folder of artifacts before `rm`: untracked files cannot be recovered. Check removed web routes from the page's own origin: from outside the page every POST answers 403 "A write is taken only from the web GUI's own page.", so that proves nothing; from the page a removed route answers 404 "No such write". Running servers keep the old tools until restarted, so say so. Spec records and skills that still name the removed thing are the person's to edit unless the ticket names them for deletion; list them in the report.

## Web page and browser tests
Make the page change surgically; a new POST route is classed in `route_class` (`web/server.py`) in the same change, or a Node member gets 403 on it (see `metaform-node-hosting`). Then make every browser test that touched the old control pass against the new one. Run `node --check` on each changed part. A key that starts a mode (listening, a menu) must not leave focus in a text box, or the next press of that key types instead. To check the page in a real browser, run a private server on a temp home and a non-default port, and stub the voice endpoints: `references/web-browser-check.md`. From an agent session, unset `METAFORM_ROLE`, `METAFORM_SESSION`, `METAFORM_WORK` and `METAFORM_NODE` before starting it, and in the same shell before each `-m browser` test run, so the server or the test's CLI calls do not inherit the session's own role or node; after `metaform web stop`, confirm the port refuses connections and delete the temp folders. A picture taken from any camera other than the person's (`web look`) needs the 3D signs turned for that render, and the check must read a known label in it: same reference, section "Pictures from another camera". Full rules: `references/web-page-changes.md`. A browser check that a path filter skips in CI is not run by any other step, so a change to the chassis that the page reads (`src/metaform/data/`, `settings.py`) reaches the page with no browser test unless the filter names it; say so in the report.
A filter on what the map draws (depth, toggles) must apply in every builder, the 3D `graphData` and the 2D `build2D` alike, or the two maps diverge; a browser test asserts both maps draw the same ids. The settings screen shows one page at a time, and it opens on Modules (`keptPage` in `screen.js` defaults to `modules`, remembered in localStorage `metaform.settingsPage`). A row on another page needs its page picked first: `page.click('#settings .setpicker > button')` (`data-focus="page-picker"`) then `page.click('#settings button[data-focus="page:<owner>"]')`, where owner is `chassis` for chassis settings (`debug`, `connect_instructions`, `roles_without_authority`) or the module id. Without the pick the test waits on a row that is not drawn and times out at its first step. When a control's behaviour changes, grep its part's header comment and the module README for the old wording: `separated by commas` survived in `screen.js`'s header after the control changed. A page control that stores a `risky` choice asks through `confirmAct` and sends `confirm`; its browser test picks Cancel first and asserts the old value is kept, then confirms. Settings saved from the page are asynchronous: a browser test that reads `/api/settings` right after a key press polls until the value appears, and never asserts once. Console errors are checked too (`problems`): 3d-force-graph logs `node not found: <id>` for any link whose end is not a drawn node, so a link to a hidden parent is dropped before the graph is fed. An event handler that awaits before it reads `event.currentTarget` gets null after the await: copy the element into a `const` before the first `await`, and re-enable that same element when the write is refused, or the control stays disabled or marked `chosen` (the permission card in `session/tools.js`, Resume in `session/text.js`). A read never writes: `followView` in `views/settings.js` saved `web_graphics` on every settings read, and the load of the page was the write; a setting is saved only by the person's act (VIEW-011). A mascot or agent act that opens a box calls that box's opener (`openFor`), never the overlay stack's `opened()`, which returns quietly for an unknown box, so `web open` reports success and does nothing. The verb answers only after the page does: `open` must be in `MASCOT_ASKS` (`web/server.py`), and `openFor` returns `{error}` for a ticket not on the map, a pane not found or with the workspace off, or an unknown `what`, which the CLI and MCP exit non-zero on. The workspace has two layouts: `WS.on` is true only in the grid, while `WS.active` is true in the grid and the classic framed layout alike (the default). `openFor` must check `WS.active`; checking `WS.on` refused every real pane in the default layout. When the page answered and refused without a `next`, the CLI hint is `metaform web viewing`, since the page is open; `open the page on this project` is only for when no page answered. A verb noun named `id` never reaches the page: `mascot_request` overwrites the payload's `id` with its own request token and the page answers under that token, so send the noun under another key (`which`, as `open_on_page` does) and keep `id` for the answer. Any new mascot act with an `id` noun needs the same rename. A mode the person turns on that must survive changes of target (the agent view, `EYE.agentMode` in `page/app/figures/eyes.js`) is its own flag: never inferred from the derived state (`EYE.agent`, whether eyes are showing now). Target keys such as A read the flag and never clear it; only the mode's own key, or a swap that ends it, clears it. A tween that returns to the person's view saves the resting camera only when no save is held, because a re-entry while the camera is still easing back otherwise overwrites the return point with a midway pose.

## Sending project text out
A module that sends project text to a third party (a hosted model, an API) checks the person-only `jev` setting before every request and sends only through `metaform.jev`, the public base. An API key in the environment is not consent: people set `OPENROUTER_API_KEY` for other tools. Agents cannot set `jev` over MCP, so when it is off no caller can send. Every send path checks it, including a resumed run, so a run prepared while `jev` was on sends nothing after it is turned off. A verb that can send out declares `open_world=True`, never `effect='read'` with a read-only or idempotent hint, and a subscriber that can reach the network is declared on the tool that triggers it. The mcp module's `test_every_verb_that_reaches_the_network_or_writes_declares_it` (`src/metaform/modules/mcp/tests/test_mcp.py`) enables every module and walks each verb's calls from source: it fails on a network reach without `open_world`, and on a `read` verb that writes the map or settings or sends through `metaform.jev.post`. A connection to 127.0.0.1, localhost or ::1 is Metaform's own process, not open world; bookkeeping (tables made on first use, caches, the shown-once record) is not a write. Run it after changing any `effect` or `open_world`. Effect also feeds consumers that filter by it, such as `dispatch:read` withholding, so check those in the same change.

## Driving an agent body
Since 2026-10-14 (ticket code.interface.graphical#28, uncommitted until Rich says yes) `web_embody` from any agent, the system agent included, gives it its own figure; only a body the person gives the system agent is the mascot. `web_go`, `web_move`, `web_turn`, `web_point`, `web_emote`, `web_take` and `web_release` act on the caller's own figure when it has one, else the mascot, and answer once the body is done: `at`, `heading`, `at_rest`, `stopped_by`, `asked`/`moved`, `off`, `target.distance`. Read those instead of checking each move with `web_see`. Push, drag and drop are the mascot's only. `web_see`/`web_look` list only what is perceivable (12 nearest, `more` counts the rest, distances to surface). Code pointers and observed numbers: `references/embodiment-observations.md`.

## Agent questions
Only sessions the person summons may put a question to the person: the sentinel, a talk session and the head or system agent, all started with `system=true`. `runner.create_elicitation` gates on `self.system`. Any other session (a worker, an intake, a merge preparation) has its ACP elicitation answered at once by `decided(fields)`: accept with the `decide` prompt from `prompts.xml` in each own-words field (`question_N_custom` for claude-agent-acp, the note for codex-acp), or decline when there is no such field, a field is required, or the question is a URL. Nothing is written to the node, the thread, question-waiting or the chat. Roundtable seats left Metaform on 2026-10-14 (they run in the roundtable's own MCP server), so no seat code is here. Tests that put a question to the person start the runner with `system=true`, since `Dispatch.start` takes nouns. Spec: BASE-052.

## Dispatch thread lines
Every new line in a session's thread is numbered by `signals.add_line(tx, ...)` inside the write transaction, from the rows past the writer's last-known seq. Never take a seq from a process counter: a second writer on the session (another runner, a served session) then gets the same number. `Session.table(fatal=False)` logs a failed line write and carries on, so a bug on the line path stays silent; test line writes through the thread itself, as `test_a_second_writer_on_the_session_never_ends_the_runner_and_lines_keep_one_order` does. A `tx.rows(by=('session_id', 'seq'), after=...)` cursor must carry both values, `[seq, name]` (the key column is appended to the index's rest); a one-value cursor raises an SQL error. Reads of the thread right after `dispatch.start` can be empty: use `max(..., default=0)`, and wait with `eventually` for the lines a test asserts on. Spec: code.dispatcher.agent#12.

## Session identity
Compare whole session ids, never the short form. Codex and other agents mint time-ordered UUIDv7 ids, so sessions started in the same millisecond share their first 8 characters. Two seats whose short ids match were two sessions, each on its own model. Before concluding that sessions are shared, compare the full `session_id` values and each session's reported model (the `model` setting's `current` in its state).

## Dispatch session end states
A session's `how` text is what says how it ended; `state` alone cannot tell a stop from a failure. Only `how === 'stopped by the person'` is "Stopped" and gets Resume: `dispatch-resume` refuses a failed session with HTTP 400, so `it failed: …`, `cancelled by the person` and a session with no `how` never get Resume, and show Continue (`.again`) in the thread bar instead. Label the other ends Failed, Cancelled or Ended, with the full `how` as the title. Browser stop records live in localStorage `metaform.stopped-agents.<project>`; a line leaves that list only once a session this page resumed reads running, never for every running session, because `D.sessions` can still be stale right after a stop. Tests seed ended sessions straight into the dispatch store: `with Store('proj', module='dispatch').tables() as tx: tx.insert('sessions', {...})` with a distinct `work_id` per row and `state: 'ended'`. The model is `test_close_and_escape_preserve_a_working_system_session_and_stop_can_resume_it` in `modules/web/tests/test_chat_recovery.py`.

## Home folder and file modes
The Metaform home is its owner's alone: a new home is made 0700 and every file in it 0600. Create any SQLite file through `sqlite.private` (`src/metaform/sqlite.py`) before SQLite opens it, so `-wal` and `-shm` get the same mode; `data.private_database` already does. Write run files and state through a helper that opens with `os.open(..., 0o600)` (`web.write_run` in `modules/web`; dispatch's `migrated-dispatch-agent-options` marker is written the same way, as `source_placement`'s marker is), never `write_text` or `open` at the default mode, which makes the file world-readable first. `home.make_private()`, called from `cli._command` before anything reads the home, tightens an existing home once and records `home_private` in the chassis meta, but only after a fresh `stat` of the root shows no group/other bits, so a root still open is retried at the next start. It resolves a `METAFORM_HOME` that is a symbolic link first and works on the link's target, chmodding the root before the walk, because the walk's lstat filter skips links; it keeps an executable's owner x bit by design. Test a linked home with a real 0755 folder behind the link, passed through `run(..., env=...)`. A test that loosens files to check tightening uses 0644 for files: 0755 keeps the owner x, so the test fails on that and not on the code. Windows keeps the access its parent folder gives, so skip such tests with `os.name == 'nt'`. Known gap, not a precedent: `run/looks`, `run/captures` and voice clips are still written at the default mode inside the 0700 home. So are the top-level folders the code makes with `mkdir` (`projects/` on the first `add project`, `run`, `backups`, `node`, `relay`, `models`, `modules`, `skills`, `builds`, `cloud`, `.agents`): `Path.mkdir(parents=True)` gives parents the default mode too. They are safe only while the root is 0700; a design question for the person, not yet decided.

## Store upgrades and concurrent openers
When several processes open an old store at once (web server, MCP server, runners after a release), one upgrades it and the rest wait and read the new file. `upgrade()` in `src/metaform/data/upgrade.py` holds `<store>.upgrade.lock` (`sqlite.file_lock`) and re-reads the layout inside it. The guard against the race is `test_three_processes_opening_a_layout_10_store_at_once_all_read_it_upgraded_once` in `tests/test_store_upgrade.py`: it failed 3 of 3 runs before the lock (one process raised `disk I/O error`) and passed 5 of 5 after. The general rule and the SQLite facts behind the guard connection are in `check-then-create-under-lock`. `sqlite.file_lock` with `wait=True` gives up with `OSError` after about 10 seconds on Windows (`msvcrt.LK_LOCK`), so a waiter behind a longer upgrade fails there; raise that before relying on it for upgrades.

## Testing outbound sends and intake follow-ons
Stub `metaform.module.provided`, not an attribute of a module you imported: `intake finish` publishes `intake.finished`, the loader loads modules afresh, and a stub on an old module object never reaches the code that runs. Stub `urllib.request.urlopen`, and `subprocess.Popen` for a detached run, but a plain function patched over `subprocess.Popen` breaks `import mcp` ('function' object is not subscriptable), which is how a missed stub shows up. Turn a person-only boolean on in a test with `run('set', '--jev', cwd=folder)`. The shared client retries 429, 503 and 529, so an HTTP-error test uses a status it does not retry, such as 402. A module whose client takes an opener (paperclip's `OPENER`, passed to every `Client`, `None` meaning urlopen) is faked in its tests by monkeypatching that module attribute to an in-memory server class; the paperclip tests in `modules/paperclip/tests/test_paperclip.py` are the model. A fresh test home has `dispatch` off, so a test that needs dispatch's cancel or stop runs `run('enable', 'dispatch', cwd=folder)` first; a bare `assert paperclip._on_surface(...)` is not an enable. `Store.add_work` at an Address with no current element stores the record as given and raises nothing (BASE-044), so a test that needs a store refusal injects a `StoreError` with monkeypatch.

## Intake notes and the base layer
The base holds RE, PE, OP and EF only. An intake note given without a condition is the node's one item of layer `critic` (`_beside` in `modules/intake/__init__.py`), never a base `note`. `data/writes.py` `base_only`, called by `writes.edit` and `layering.refine`, refuses a non-empty note on a base element or join; clearing one to None is allowed. Read a node's note with `map node node=element:<address>`; `map knowledge op=list` does not exist. A one-time move of notes already in a real base is held as a patch under `artifacts/critic/` until the person says apply, because the first map call from any process runs it on the real home. Verify it only on a scratch home. No specification record states the base-only rule yet; the person decides that wording.

## Tests everywhere
From an agent session, unset `METAFORM_ROLE`, `METAFORM_SESSION`, `METAFORM_WORK` and `METAFORM_NODE` in the same shell before any `pytest` run, so the test's CLI calls do not inherit the session's own role or node. Run only filtered tests, `uv run pytest FILE -k NAME -q`. Two-home tests (one project folder registered in two `METAFORM_HOME`s): a run.json fixture takes its `base_id` from `home.add_base(project, name).id` in the home that will read it, created before the run is written, because `pipeline._load` refuses a base that home lacks. To check a home holds no run, look at `home.project_folder(id)/'source_placement'/<run>`, never `home/'projects'/id`, which is never created and makes the assertion vacuous. Do not call `runs_root` in an assertion, since it creates the folder. Every test file needs a kind marker, `pytestmark = pytest.mark.kind("simulation")` (or `fixture`, `real`), or collection refuses each test in it with "no @pytest.mark.kind". A module with no tests folder gets a test file only when the person asks for one. Never run the full suite except for a final deployment check. Test folders have no `__init__.py`, so pytest imports each test file by its bare basename: two files both named `test_skills.py` (`mcp/tests` and `workflow/tests`) made a whole-tree run stop at collection with `import file mismatch`.
