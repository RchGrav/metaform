# Changing Metaform

Read the one subfile for the class of work you are in before editing. Each rule came from a real defect in this repo.

## Tickets and source passes
Report each step with `metaform map work op=step`, and close with `op=done` only after the acceptance checks pass. Never edit a spec record from a ticket; the person writes specs. A worker agent cannot `op=add` a ticket (refused: tickets are written by the person and the agents that serve them), so a follow-up ticket goes into its own ticket's `op=edit` note for the orchestrator to file. Spec text drafted for the person goes to `artifacts/specs-draft/`, never `specifications/`. When a design is replaced, delete the memory observations that describe the old one. When a notice says a ticket's task has been replaced, re-read the ticket with `map_work` before more work, and do not restore the replaced behaviour. A ticket assigned to one module does not edit `src/metaform/*.py`. In a shared tree where another agent already has uncommitted edits in a file, change only your own lines and do not commit without the person's yes. Full rules, including source passes and refactor runs: `references/ticket-work.md`.

## Module verbs and settings
A verb or setting lands as one unit: the module's `__init__.py` declaration, its `README.md`, its `CHANGELOG.md` Unreleased entry, and the spec bullet it cites, with tests in the module's existing test file. A fixed set is a choice setting, never free text. A setting holds a whole number only (`settings.number`), so a dollar or other fractional limit is a whole-number setting, and the fraction is taken as the verb's argument (`spend=0.50`). A limit the person marks `person_only` binds agents too: a verb that takes an agent-supplied override may only tighten the setting, and refuses a looser value saying only the person can raise it. Independent choices get one setting each: a single list setting holding many entries loses the others whenever one is saved. Changing what a stored setting means needs a one-time migration, run from the module's start hook through the public `home.save`/`home.clear` calls so caches and change notices stay right. Processes started before the change (the MCP server, live agent runners) still read the old declaration until restarted; say so in the report. Tab completion for a setting's choices works through `complete -C metaform metaform`, and module discovery must run inside that path too. Full rules: `references/module-changes.md`.

## Web page and browser tests
Make the page change surgically, then make every browser test that touched the old control pass against the new one. Run `node --check` on each changed part. A key that starts a mode (listening, a menu) must not leave focus in a text box, or the next press of that key types instead. To check the page in a real browser, run a private server on a temp home and a non-default port, and stub the voice endpoints: `references/web-browser-check.md`. A picture taken from any camera other than the person's (`web look`) needs the 3D signs turned for that render, and the check must read a known label in it: same reference, section "Pictures from another camera". Full rules: `references/web-page-changes.md`.
A filter on what the map draws (depth, toggles) must apply in every builder, the 3D `graphData` and the 2D `build2D` alike, or the two maps diverge; a browser test asserts both maps draw the same ids. Settings saved from the page are asynchronous: a browser test that reads `/api/settings` right after a key press polls until the value appears, and never asserts once. Console errors are checked too (`problems`): 3d-force-graph logs `node not found: <id>` for any link whose end is not a drawn node, so a link to a hidden parent is dropped before the graph is fed.

## Driving an agent body
Since 2026-10-14 (ticket code.interface.graphical#28, uncommitted until Rich says yes) `web_embody` from any agent, the system agent included, gives it its own figure; only a body the person gives the system agent is the mascot. `web_go`, `web_move`, `web_turn`, `web_point`, `web_emote`, `web_take` and `web_release` act on the caller's own figure when it has one, else the mascot, and answer once the body is done: `at`, `heading`, `at_rest`, `stopped_by`, `asked`/`moved`, `off`, `target.distance`. Read those instead of checking each move with `web_see`. Push, drag and drop are the mascot's only. `web_see`/`web_look` list only what is perceivable (12 nearest, `more` counts the rest, distances to surface). Code pointers and observed numbers: `references/embodiment-observations.md`.

## Agent questions
Only sessions the person summons may put a question to the person: the sentinel, a talk session and the head or system agent, all started with `system=true`. `runner.create_elicitation` gates on `self.system`. Any other session (a worker, an intake, a merge preparation) has its ACP elicitation answered at once by `decided(fields)`: accept with the `decide` prompt from `prompts.xml` in each own-words field (`question_N_custom` for claude-agent-acp, the note for codex-acp), or decline when there is no such field, a field is required, or the question is a URL. Nothing is written to the node, the thread, question-waiting or the chat. A roundtable seat keeps its decline. Tests that put a question to the person start the runner with `system=true`, since `Dispatch.start` takes nouns. Spec: BASE-052.

## Dispatch thread lines
Every new line in a session's thread is numbered by `signals.add_line(tx, ...)` inside the write transaction, from the rows past the writer's last-known seq. Never take a seq from a process counter: a second writer on the session (another runner, a served session) then gets the same number. `Session.table(fatal=False)` logs a failed line write and carries on, so a bug on the line path stays silent; test line writes through the thread itself, as `test_a_second_writer_on_the_session_never_ends_the_runner_and_lines_keep_one_order` does. A `tx.rows(by=('session_id', 'seq'), after=...)` cursor must carry both values, `[seq, name]` (the key column is appended to the index's rest); a one-value cursor raises an SQL error. Reads of the thread right after `dispatch.start` can be empty: use `max(..., default=0)`, and wait with `eventually` for the lines a test asserts on. Spec: code.dispatcher.agent#12.

## Session identity
Compare whole session ids, never the short form. Codex and other agents mint time-ordered UUIDv7 ids, so sessions started in the same millisecond share their first 8 characters. Two seats whose short ids match were two sessions, each on its own model. Before concluding that sessions are shared, compare the full `session_id` values and each session's reported model (the `model` setting's `current` in its state). A roundtable table's `status` gives each harness seat its whole `session` and its `reported` model.

## Tests everywhere
Run only filtered tests, `uv run pytest FILE -k NAME -q`. Every test file needs a kind marker, `pytestmark = pytest.mark.kind("simulation")` (or `fixture`, `real`), or collection refuses each test in it with "no @pytest.mark.kind". A module with no tests folder gets a test file only when the person asks for one. Never run the full suite except for a final deployment check. Never `git stash` in the shared tree, and do not copy a file aside to test the code without the fix while another session is editing it: the swap breaks that session's work. When an Edit fails with "File has been modified since read", re-read the exact spot and edit again; another session is writing the same files. Pyright strict flags `.get()` on a value typed `Any` or `Unknown` as partially unknown; cast the dict first (`cast(dict[str, Any], reply).get('usage')`), then narrow with `isinstance`. A test that starts a dispatch runner stops it before it returns (`run('dispatch', 'stop', ticket, cwd=mapped)`); otherwise pytest reports the runner as left running. A lambda built in a loop that reads the loop variable trips ruff B023: bind it as a default (`eventually(lambda count=position + 1: ...)`). A walrus (`:=`) inside a comprehension's iterable is a SyntaxError that takes the whole file down at collection (INTERNALERROR), so hoist the read into a named `def` and pass that to `eventually`. After inserting a test into an existing file, Read the seam: lines that belonged to the test above can end up inside the new one, as a `refused = run(...)` did before it was moved back.
