# Working a Metaform ticket, source passes and memory

## Reporting
- Report each finished step as you go with `metaform map work op=step id=WORKID said="..."`, and close with `op=done resolution="..."` only after the acceptance checks pass. Each step's `said` names what changed, why, and what was left out and why.
- Before ending a turn while a ticket is open, including while background reader agents still run, run `op=edit note=...` so the note says what has run, what is pending, and what has been written. Do not rely on the chat reply to carry that state.
- A ticket whose fix runs in a background subagent stays open. Close it with `op=done` only after reading the subagent's report and re-running the checks yourself.
- Read the ticket back after a write. If `op=plan` (or any write) returns the ticket node without the recorded line, run `metaform map where ADDRESS full=true` or `op=edit note=` to confirm it landed. Never assume a plan was stored because the call returned without error.
- An acceptance check that needs an agent verb run from a new session cannot pass from the session that wrote the change: its runner predates the new op and refuses it ("No request attach."). Leave the ticket open, name that check as the open step in `op=edit note=`, and do not count the refusal as a pass.

## Scope and decisions
- Chassis is not a module ticket's to change. A ticket assigned to one module (dispatch, web, memory) does not edit `src/metaform/*.py` or another module. If the fix covers only part of the chain (the ticket's suggested argument reaches the verb but not the runner or agent behind it), record the gap and the options in the step and note with `op=edit note=`, keep the ticket open, and leave the core change for the person.
- Spec records: the person writes the specs. Do not edit a spec record from a ticket. Name the file:line in the step and put draft wording in the note with `op=edit note=`.
- Shared spec records: when sibling tickets edit the same record, do not fold its stacked amendments into the body. Edit only your own lines and name the unmerged amendments in the step.
- Decisions the ticket does not own (an authored prompt, a policy): ship it gated off, with the authored element empty (an empty element turns the feature off). Keep the ticket open and put the pending decision, its draft and open issues, in the note.
- Authority changes: when a change alters who may write or stop, test both sides with one happy path (the held role is refused, and the person's or system's write goes through), and report what the page still allows.
- Stale premises: named inputs may be stale. Before relying on a path the ticket cites, confirm it exists (Read, or `ls`/`test -e` on the absolute path). A missing file is a stale premise: say so in the step and carry on with the files that exist. A file named without its folder is not proof of absence: locate it with Glob or `ls -R` under the repo first and record the path you found.
- Bash `cd` persists between calls, so use absolute paths for files under `artifacts/`.

## Reading the map
- Help takes the module first: `metaform help map work`, `metaform help map knowledge`. `metaform map help knowledge` fails with "Error: map has no verb help."
- `metaform map where ADDRESS full=true` prints labeled lines (`provides:`, `receives:`, `work:`, `layers:`, `past_work:`), each followed by one JSON value. Split each line on its first colon before parsing.
- Open work on one join: `metaform map work receiver=R provider=P`. Join ids come from the element's `provides:` line in `map where ELEMENT full=true`. `metaform map where join:ID` returns no output, so do not use it to read a join.

## Memory
- Memory list arguments: pass a bare JSON array of names to `metaform memory open_nodes`. `'{"names":[]}'` returned empty results with the notice "names is an array; what was sent was kept as its one member". This is inferred from the notice; confirm with `metaform help memory` before relying on it.
- Read before you write: `map where ADDRESS full=true` prints a `memory:` line with the entities and observations at that node. Check it for an existing observation before adding one, so a node does not collect duplicates of what a sibling recorded.
- Stale memories: when your change makes a stored memory false, delete that observation with `memory delete_observations` and add the correction with `memory add_observations` in the same step. Copy the stale observation's exact text from `memory open_nodes` into the delete call. Never use `delete_observations` as a probe with a guessed or shortened string: it reports success even when it removes a still-true line. If one is removed by mistake, add it back word for word in the same step and say so. Then record the new facts at the ticket's node with `memory create_entities`.
- Citations: when recording a finding about code, pass `cite` with the file:line ranges it rests on, for example `"cite":["src/metaform/modules/web/page/app/figures/attention.js:113-143"]`. A later reader can then see which memory is stale when that code changes.
- JSON from the shell: observations often hold apostrophes, which end a single-quoted argument. Put the JSON in a heredoc: `E=$(cat <<'EOF' ... EOF)`, then `metaform memory create_entities "$E" node=NODE`. Each entity needs a `title` (one line saying what it is) beside `name`, `entityType`, `why`, `cite` and `observations`; without it the call is refused with "has no title" and nothing is stored. Ticket notes take the same heredoc with `op=edit note="$N"`.

## Tests and checks
- Run only the filtered tests you wrote: `uv run pytest FILE -k NAME -q`. Report pre-existing type-checker errors as outside your change, with their line numbers.
- Signature changes: grep the tests for monkeypatch stand-ins (`grep -rn "'NAME'" src/metaform/modules/*/tests tests`) and widen any positional-only stand-in to `*args, **kwargs`. A stand-in that rejects a new keyword fails only where that keyword is passed, so it is missed when the change runs in isolation.
- Fixtures that seed tickets: assert membership (your ticket is in the result), not equality to one item, because the shared fixture already holds a ticket.
- Test homes must clear `METAFORM_ROLE`, `METAFORM_SESSION`, `METAFORM_WORK` and `METAFORM_NODE` (the conftest home fixture does this). A test that needs a role sets it through the command's `env=`. Otherwise a worker's ticket write is refused for the wrong reason.
- Never run `git stash` in the shared tree. `page/app/` is untracked, so stash saves nothing there, and a later `git stash pop` applies an old, unrelated stash. To test without the fix, copy the file aside, restore it, and copy it back.
- Adapter claims: a claim that an external agent adapter does something (subagents, images, timers) is checked against a recorded real session, not the adapter's capability flags. Find the child or event in the session data first.
- codebase-memory from the shell: passing a raw JSON argument to `~/.local/bin/codebase-memory-mcp cli TOOL` is deprecated and warns on every call. Use the tool's flags (`cli TOOL --help`), `--args-file PATH`, or piped stdin.

## Source-pass tickets (code read against element joins)
A source pass records how code realizes each purpose join an element provides. It changes no code and never edits the map; the map's statements are the person's.
- Decomposition uses only ordinary elements and purpose joins. A smaller part of a coarse element is its own providing element, joined by a purpose join to the functional parent. There is no subtype field and no subtype join type; purpose is the only join type. Do not record parts as "subtype" joins, even where an older intake prompt says so: that wording is stale, so report it rather than follow it.
- For each join, find the realizing code with codebase-memory, then read it as a critic against the join's purpose and ef. Check coverage and read any missed range directly before relying on it.
- Record each seam with `metaform map knowledge op=add-item layer=sources node=join:ID`, with refs only for the functions that carry the purpose. Pass `value` as a JSON object with `realized_by`, `read_with` and `on` (the date), and pass `refs` as a JSON array of pairs: `["path", "src/..."]` for files and `["qn", "FULL.QUALIFIED.NAME"]` for functions, using the full name codebase-memory returns. Build both in a heredoc or script file, not inline quotes.
- Purpose with no code under it: open a held gap at the join with `metaform map work op=add receiver=R provider=ELEMENT held=true condition=missing note="what is absent and where you looked"`. Code that does not do what the join says: a held task at the join naming file:line. Code under the element that serves no join goes in the resolution.
- Before writing a gap, read open work at that join (`metaform map work receiver=R provider=P`); if a sibling already recorded it, do not duplicate it.
- Dispatched workers cannot open held work: when `METAFORM_ROLE` is set to a worker, `map work op=add` is refused with "A worker agent writes no ticket". Put each gap in your own ticket's note with `metaform map work op=edit id=WORKID note="..."`, one line per gap with its file:line, and say in the step that the held tasks await the person or the orchestrator. Do not retry the add. Workers can still write sources items and memory; only tickets are refused. Check `echo $METAFORM_ROLE` before the first gap write.
- Reader subagents: every brief says change no file, write no map or memory, run no tests, and report back. Their results are not yours until read and recorded. Background readers do not survive a session pause: after a pause, list their output files first, and relaunch only the chunks with no or partial output, telling each to continue after the last item already written. Re-read any cited file:line yourself with `sed -n` before recording a reader's gap; a reader's claim is a lead, not a finding.
- Placement batches (refactor remainder): every placement attaches to the provider element as the receiving element (`Node('element', provider)`), never to a purpose or join record. Split pending items into chunks by line range; each reader gets a chunk file and a category file, and writes one JSONL line per item `{"item","provider","why"}`. The brief limits `provider` to the category set, cites the decisive app.js line, and forbids any Metaform MCP call. Check every line before applying: the provider exists in the run's candidates, `why` is non-empty, and the item id is in the pending set. Root `code` is never a placement: hold any line with provider `code` (including a Jev suggestion) out of apply and list it as unresolved for a second source pass that finds a specific provider. Exclude `code.controller.build`. Enforce this in the apply script and in every reader brief, since readers already running may have read an older brief. Before resuming a refactor run, confirm the accepted placements contain no root `code` selection. Record each with `metaform refactor resolve run=RUN base=BASE item=ID provider=P why=TEXT`, one call per item, and log applied ids so a rerun skips them. `resolve` refuses an item not in the review queue, a provider outside the run's categories, and a second, different placement for the same item.
- Refactor run files: `.metaform/refactor/RUN/` holds `input.json` (items; candidates keyed `category_NNN` with `provider` and `ef`), `decisions.json` (per item `candidate_id`, `confidence`, `probabilities`) and `resolutions.json`. Items below the run's threshold with no resolution are the pending queue. Copy a working set out to `/tmp` before reading it, and do not write into the run folder by hand.
- Queue paging: `refactor_pending` takes `limit` from 1 to 100 and `offset` of 0 or more. `limit=0` is refused, so never send 0 to read a count; read `remaining` and `total` from a small page. A page of 100 can exceed the tool-result cap and is saved to a file: read it with `jq` or `python3 -I`, not Read, and advance `offset` until `remaining` reaches 0.
