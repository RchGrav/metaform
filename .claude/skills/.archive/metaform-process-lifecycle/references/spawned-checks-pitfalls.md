# Spawned checks and probes: pitfalls

Each item came from a real run. Read the one that matches the failure.

- A probe script that uses top-level await takes a `.mts` extension and runs as `npx tsx file.mts`. A `.ts` file outside a `"type": "module"` package compiles to CJS under tsx, and esbuild rejects top-level await. Renaming fixes it without changing project config.
- Start subprocesses from a plain `def`, not inside `async def`: ruff ASYNC220 rejects `subprocess.Popen` in async code. The sync helper returns the process list; the async body runs the checks.
- Pick ports by binding a socket to port 0 and reading it back. Poll with `connect_ex` until the port answers, and fail with a clear message if it never does. Never run two copies of a check that picks ports with a free-port helper at once: the first run's teardown can kill the other run's server.
- Drive fake agents and peers by environment variables, one log path each. Give a fake agent a gate file (`FAKE_ACP_SAY_GATE`): it waits until that file exists before it starts output, and the test creates the file only after the page and its observer are in place. A fake that streams from spawn races the page's open.
- Set the agent explicitly in a scratch home. A fresh home defaults the dispatch agent to the real CLI, so a fake without `--dispatch-agent claude` starts a real agent. A dispatch agent set from the repo folder is stored at that folder's scope; a scratch project in another folder then starts the real agent. Save the fake with a folder scope that covers the scratch projects, and set it before the run that depends on it.
- Pop inherited `METAFORM_WORK`, `METAFORM_SESSION`, `METAFORM_ROLE` and `METAFORM_NODE` before a probe runs. A probe run from a dispatched worker with `METAFORM_ROLE=worker` gets `started: []` from `dispatch autostart` with no error. That is the inherited role, not a code bug, so check the environment before debugging the code.
- Never start a scratch Metaform web server on a home copied from the real `~/.metaform`. The copied dispatch tables make the server resume the person's system agent on start, and those settings are person-only. Use a fresh empty home and a PATH holding no agent command (`npx`, `claude`, `codex`, `gemini`). Check that no `dispatch.sessions` row was added after the start.
- A foreground server trial goes under `timeout -s INT N` in its own scratch home, with `BROWSER=true` and the role variables unset. Exit 124 is the timeout firing, not a failure. The proof of a clean stop is the server's own stop line in its output and log; read both.
- A fake intake or worker agent stays in its session until something stops it. Stop it through the product's own verb: list sessions with `metaform dispatch sessions thread=false --json`, then `metaform dispatch stop WORK_ID`, and read its `stopped: True` line. Matching processes by path with kill is the last resort.
- Stop a spawned tree by its process group, not its top pid. `terminate()` on the top process left a demo's web server and four of its agents running. Start with `start_new_session=True` and send `os.killpg(pgid, signal.SIGINT)`. On Windows, start with `CREATE_NEW_PROCESS_GROUP` and send `CTRL_BREAK_EVENT`.
- Stop a stub server by the pid recorded when it started, in the teardown. `pkill -f PATTERN` matches the shell running the check when the pattern sits in its own command line, and the call exits 144. A stub left by an aborted run keeps its port, so use a fresh port per run.
- A teardown sweep that ends leftover servers by name or port also ends other sessions' live servers. On ticket #92 a test run ended four `metaform.modules.web.server` pids that belonged to another worktree, and they were back within a minute. Check `/proc/PID/environ` for the owning home before ending any pid, and report any foreign hit instead of ending it. The sweep is a defect to ticket, not a setup step to keep.
- Scan `/proc/*/environ` for the scratch home's `METAFORM_HOME=` path, and stop any hit. A stub runner (`python -c 'import time; time.sleep(600)' dispatch run WORK_ID`) left by a browser test outlives its test process: run `ps -eo pid,etime,args | grep 'dispatch run'`, tie each match to your run through its sessions row pid, and say so in the report when you cannot tie it.
- A probe that starts detached children must find and kill them after it ends, found by the scratch home in `/proc/PID/environ`. A test that kills an orphaned runner proves it is gone by its reaped state (`runner_of(pid) is None`), never by a failing `os.kill`, because an unreaped zombie still accepts `os.kill`.
- Under `set -u`, a missing positional argument aborts the script before its cleanup line. Check the arguments first.
- Find a scratch file in the folder the check created, not with `find /`. A whole-filesystem find on WSL ran for minutes and had to be stopped.
- Wrap any probe that can block (a lock wait, a retry loop, a server that never answers) in `timeout N`, and keep foreground probe calls short.
- A periodic loop (a watcher that syncs every N minutes) is verified only past its first pass: wait for its record file, sleep past that first run, assert the item is still open, then change the item and time the later close.
- After SIGTERM to a spawned watcher, wait a couple of seconds and assert its record file is gone. A surviving record means the cleanup path did not run.
- A fake transport that a test drops on purpose must itself hold the reader's stdout pipe, as ssh does. Write it as a small relay that owns the pipe and forwards to the child, and confirm that killing it gives the reader EOF before trusting the test.
- A child process that must run a worktree's code is not started with `python -I` and only `PYTHONPATH` set: `-I` drops `PYTHONPATH`, so an editable install loads the main checkout. Put the tree's `src` on `sys.path` inside the child and print the package's `__file__` before blaming the fix for a hang.
- Before blaming a fix for a check that fails only in some runs, run the same check on the reverted copy. A failure on both is a flaky check: record a follow-up, do not call it a regression.
- Print the verdict only. Assert on the record's fields or the one line the code produced, not on a substring that prompt text can also contain.
- Restart a scratch server after editing its code, before probing it. A 404 on a route you just added means the running process predates the edit.
- To test crash recovery, SIGKILL the server by the pid its own run record names in the scratch home, never by name. Kill the server, not its supervisor, then read the supervisor's restart line and its cause.
