# Roundtables open on the question alone; a fresh Planner writes the proposal

A roundtable starts from the person's question and nothing else. It is never limited to a selected part, and it is never limited to the project: no outline or project-wide memories are loaded as its grounding. The seats look things up on the map through their own tools when the question touches the project.

- T opens a table that asks only for the question. A part selected on the map focuses the table on that part; with none selected, nothing is focused.
- The table exists to produce a proposal. The engine writes only the mechanical record (ideas, rankings, vote count) to `docs/roundtables/<folder>/mechanical-report.md` and `export.json`. When the person ends the table, that record is sent as a prompt to a fresh Planner context (`orchestration_delegate` role=planner). The Planner writes `proposal.md` beside the record: the answer to the question, where seats agreed and disagreed, what is open, an ordered plan with a done-check per step, and the decisions the person must make. It commits and pushes that file and the person gets a link. The Planner checks every rank, vote count or "all seats" claim it takes from the table's report against `mechanical-report.md` before writing it, since the record is the source: on 2026-10-21 report.md said all four seats put idea I1 in their top seven, while the rankings in `mechanical-report.md` put I1 14th for one seat, and the proposal must state that disagreement rather than repeat the report. The record files (`mechanical-report.md`, `export.json`) can be untracked in the project folder; copy them into the proposal's worktree and commit them beside `proposal.md`, leaving the report itself unchanged. Before committing, check the project folder for untracked copies at those same paths: a landing into main refuses any delta file that already exists untracked there, even with identical bytes. If `cmp` shows the untracked copies identical to the committed ones, remove the untracked copies from the project folder and retry the landing with `metaform dispatch merge id=<work id>`; see `metaform-ticket-landing`. The system agent only routes the prompt; it does not write the proposal and does not carry the transcript in its own turn. Do not give the proposal to a reporter seat.
- An adopted idea may concern nothing that exists yet. Do not force it onto the nearest element. With no part, file its ticket at the project's top element, or at the proposed address only when the report names an address that already exists. Kind enhancement, with the idea and any proposed address in the note.
- No ticket starts from a table before the person has read and approved its proposal. The proposal names the tickets and their order; they are filed only after that approval.
- Never write a placeholder address into the map. Tickets never change the map.
- The key help text describes the question, not a selected part.

## Proposals that follow a table
- A proposal is written as `proposal.md` beside the table's record (`mechanical-report.md`, `export.json`) in the table's folder under `docs/roundtables/`. It files no tickets: the person approves the plan first.
- An earlier round's plan is cited by relative path, with its ticket names and decision ids kept. Each change to it is marked with its why, and the plan names the seams it fits.
- If that earlier plan lands on main while the proposal is being written, rebase onto main and re-check every citation against the landed text before the final commit. Grep the proposal for each retired ticket id afterwards.
- The Roundtable 2 engine ships inside Metaform as the vendored package `metaform.modules.roundtables.roundtable`. Never install it, never look up a `roundtable` command on PATH, and never add a `roundtables_engine` setting or an "engine not found" path. Every engine process starts as Metaform's own interpreter running `-m metaform.modules.roundtables.roundtable`, so it works in a clean environment.
- Tests for the roundtables module run the vendored engine with its fakes from `roundtables/tests/`, with no checkout and no PATH entry. A test that needs a failing engine sets `ROUNDTABLE_HOME` to a regular file.
- The web page's roundtable stage is watch-only: it asks the question once and then the seats talk among themselves. Do not add chair controls or chair endpoints to the page. The chair verbs stay on the CLI and MCP.
- The Roundtable 2 engine is vendored inside the module as `metaform.modules.roundtables.roundtable` (copied from RchGrav/roundtable at 65359b2; that repo is private and not on PyPI, so a dependency would fail for every other install). Every engine process starts as Metaform's own interpreter with `-m metaform.modules.roundtables.roundtable`. Never look a `roundtable` command up on PATH, and never bring back a `roundtables_engine` setting or an install-the-engine refusal.
- The engine keeps its own home in `ROUNDTABLE_HOME` (default `~/.roundtable`). The module's tests carry the engine's fakes in `roundtables/tests/fakes.py` and `roundtables/tests/fake_agent.py`, so they run without a checkout.
- The page's roundtable stage is watch-only: the person asks the question once and watches. Chair controls (hold, continue, advance, end) live only in the CLI and MCP chair verbs; do not add them back to the page or the server.
