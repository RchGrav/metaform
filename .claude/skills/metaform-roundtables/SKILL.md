# Roundtables open on the question alone; the system agent writes the report

A roundtable starts from the person's question and nothing else. It is never limited to a selected part, and it is never limited to the project: no outline or project-wide memories are loaded as its grounding. The seats look things up on the map through their own tools when the question touches the project.

- T opens a table that asks only for the question. A part selected on the map focuses the table on that part; with none selected, nothing is focused.
- The table exists to produce a report. When the person ends it, the person's system agent writes the full outcome: the question, each seat's position and reasoning, where they agreed and disagreed, what was settled and what is open, and the ideas worth acting on. The report is saved where reports are saved today; the person gets a link and a few lines in chat. The system agent reads the table's record on demand and does not take the whole transcript into its turn. Do not give the report to a reporter seat.
- An adopted idea may concern nothing that exists yet. Do not force it onto the nearest element. With no part, file its ticket at the project's top element, or at the proposed address only when the report names an address that already exists. Kind enhancement, with the idea and any proposed address in the note.
- Adopting an idea as a ticket stays available but is secondary to the report.
- Never write a placeholder address into the map. Tickets never change the map.
- The key help text describes the question, not a selected part.
